# 项目 04：综合 SaaS 毕业项目

**对应阶段：阶段 08｜建议周期：4–6 周（旧 C33–C36 仅为压缩 MVP 窗口，深度路线用 D59–D68）｜类型：独立综合交付**

## 项目目标

选择一个足够小但具有真实业务规则的问题，独立完成从需求到运维的交付。重点不是复制大型 SaaS，而是证明你能在约束下做取舍、保护数据、处理失败并持续迭代。

## 推荐选题（三选一）

1. **团队客户跟进工具**：组织、成员、客户、跟进记录、提醒和审计。
2. **小型预约管理工具**：组织、服务、可预约时段、预约、取消和通知记录。
3. **内容审核协作工具**：组织、内容、审核任务、状态流转、评论和审计。

也可以选择自己的题目，但必须保持同等复杂度，并先写出一页需求说明。

## MVP 约束

- 最多 3 条核心用户路径、6–8 个核心实体、2–3 种角色。
- 多租户只支持“一个用户可属于多个组织”或“单组织用户”之一，先明确模型。
- 通知优先记录出站事件或使用可控替身，不依赖多个第三方平台。
- 文件功能若非核心可删除；若保留，必须限制类型、大小、路径和访问权限。
- 后台任务优先单进程可靠实现或简单持久化任务表，不默认引入队列集群。

## 必须交付

### 需求与设计

- [ ] 目标用户、当前流程、痛点证据、用户故事、非目标和成功指标；真实访谈与角色模拟分开标注。
- [ ] 核心规则各有“给定—当—则”验收示例，覆盖正常、失败和边界。
- [ ] 领域规则、状态机、权限矩阵和关键数据不变量。
- [ ] “用户故事 → 业务规则 → 测试 → 证据”追踪表，以及一次需求变更的取舍记录。
- [ ] 系统上下文图、应用架构图、ER 图和核心 API。
- [ ] 至少三份 ADR：认证、多租户隔离、事务/后台任务等关键选择。

### 功能与安全

- [ ] 注册登录、组织切换、成员邀请和角色权限。
- [ ] 核心实体 CRUD 与至少一个非平凡业务状态流。
- [ ] 所有查询和变更都有组织边界，服务端验证资源归属。
- [ ] 高风险操作有审计记录；审计内容可追踪但不泄露秘密。
- [ ] 至少一个幂等或并发场景，例如重复预约、重复邀请或状态竞争。
- [ ] 输入、上传、速率、会话、错误和日志均有安全边界。
- [ ] 用户数据清单包含用途、角色、保留、删除和第三方流向；至少一条跨租户读取或删除规则有自动化测试。

### 质量与运行

- [ ] 单元、集成、权限、并发和关键 E2E 测试。
- [ ] CI 执行格式、Lint、类型、测试、构建和必要扫描。
- [ ] HTTPS 部署、配置管理、结构化日志、核心指标和健康检查。
- [ ] 数据库迁移、备份恢复和回滚演练有记录。
- [ ] 一个依赖失败或流量增加场景的降级/容量分析。
- [ ] 一次高风险 diff 的正式自审与 AI/同伴复审记录，结论和修复可追踪。
- [ ] 记录真实辅助方式；全路线至少一份完整 AI/同伴工单，另有关闭生成式辅助的独立交付，不强制每项目重做或购买工具。
- [ ] 安全验收映射 OWASP Top 10:2025 A01–A10，未适用项有理由，高风险问题有修复或阻断证据。

## 推荐迭代

### 迭代 1：最小闭环

- 需求、模型、权限矩阵、测试策略。
- 一条主路径从 UI 到数据库贯通。
- 本地 CI 和基础部署，不等待最后才部署。

### 迭代 2：正确性与异常

- 补齐角色、租户隔离、业务不变量、失败路径和审计。
- 加入并发/幂等实验、迁移与备份恢复。

### 迭代 3：体验与交付

- 完善可访问性、空/错/加载状态和核心性能。
- 完成 E2E、监控、回滚、README、演示与项目复盘。

## 验收标准

- [ ] 新用户不依赖开发者手工改库即可完成核心演示流程。
- [ ] 一页需求说明、验收示例和追踪表完整，需求变更有明确取舍而非直接加功能。
- [ ] 越权、重复请求、非法状态和依赖失败有明确行为与测试。
- [ ] 架构图、代码、配置和演示一致，没有只存在于文档中的功能。
- [ ] 从干净环境按文档可运行，所有关键检查有真实执行证据。
- [ ] 能在 3 分钟演示和 20 分钟技术深挖中清楚解释项目。
- [ ] 明确未实现项、已知限制、风险与下一轮优先级。
- [ ] 一个高并发或 AI 深度模块具备容量估算、压测、故障恢复和 Runbook，模拟数据与真实测量分开标注。

## 大厂深度扩展（四选一）

在 SaaS 主路径通过后，按 [[../01-阶段课程/专项-高并发与系统设计|高并发与系统设计专项]] 增加一个深度模块：

1. **高并发交易/预约**：热点竞争、幂等、排队/原子扣减、限流和一致性实验。
2. **Feed/内容分发**：读写扩散、稳定分页、热点作者、缓存去重与降级。
3. **实时通知/调度**：Outbox、优先级、公平调度、重试死信、积压和幂等消费。
4. **RAG/Agent**：混合检索、重排、引用、工具权限、评估集、Token/P95 成本和提示注入验证。

深度模块可延长 2–4 周，但必须有容量估算、同口径压测、至少两类故障注入、恢复演练和 Runbook；不得用架构图或模拟数字代替。

## 停止扩张信号

出现以下任一情况，应暂停新功能并收敛：

- 核心路径尚无自动化测试，却在增加实时、AI、支付或第三方集成。
- 权限模型频繁变化，但没有权限矩阵和跨租户测试。
- 尚未部署，却在拆微服务、引入 Kubernetes 或复杂事件驱动。
- 为保证演示而硬编码数据、跳过验证或隐藏错误。

## 从项目毕业到完整训练

此项目验收对应 G6；之后仍须主修/迁移 G7、[[项目05-陌生系统接手与团队交付|接手与团队交付 G8]]、[[../04-资源与评估/综合实操考核与上岗准入|独立综合考核 G9]]。可靠性深度模块与新增 E 实验可共享证据，未实现的 AI/实时/Feed 不因列为候选就算已掌握。
