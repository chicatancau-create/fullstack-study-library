## 一、选择训练仓库

优先选有许可、无秘密、可本地运行且复杂度可控的开源示例，或由同伴提供的合成业务仓库。也可选择自己至少四周未接触、已有提交历史的项目，但必须标记“旧项目接手模拟”，不能称为完全陌生仓库。

- 基本要求：有前后端/持久化主路径、历史变更、测试和部署说明，存在可识别模块边界。
- 不要为了训练修改真实公司仓库、客户数据或已上线用户系统；不上传无权代码。
- 若无真实 Bug，由同伴植入 2–3 个缺陷并保存答案。只有自己时可使用预制变体，但“已知缺陷自测”不等于盲测；G9 的外部性另行评估。
- 不自动创建 PR、联系维护者或发布服务。对外贡献遵守授权与贡献流程，本地交付已可训练多数行为。

## 三、缺陷与功能的建议组合

至少一项正确性缺陷与一项生命周期/体验/性能问题：

- 后端：资源归属遗漏、最后 Owner 竞态、幂等键未绑定请求体、重复消息副作用。
- 前端：过期请求覆盖、表单取消/重试丢草稿、焦点恢复失败、旧 chunk 更新故障。
- 运行：连接池耗尽、没有超时或清理、慢查询、不可回滚的 schema 变化。

功能示例：任务批量分配并返回逐项结果；预约时段改版并兼容旧调用；增加可取消的异步导出。最多一条新增核心路径，必须有失败、权限、幂等/并发或数据迁移中的相关边界。

## 四、协作闭环

1. 开工前写一页 RFC：问题、非目标、两个候选、风险、验收和回滚；请同伴评审，或明确标记自审/AI 复审。
2. 用 Issue/本地工单拆分；每项记录完成定义、依赖和估算区间，别用固定小时制造精确感。
3. 用小 diff 交付；审查评论分阻断/建议/疑问，逐条给出采纳依据、修复与验证。
4. 模拟一次优先级变化：说明对日期、范围、质量的影响；可延期次要功能，不静默降低权限或恢复要求。
5. 写一次事故状态更新：已知影响、未知项、当前止损、下一次更新时间，不编造恢复预期。
6. 交接给另一人按 README 运行、按 Runbook 处理一个故障；无同伴时用干净环境自测，外部交接仍标未完成。

同伴与 AI 不同：AI 可帮忙找候选问题，不能证明真实团队协作。课程能力评估允许自测进展，但简历必须说明实际参与者与职责。

## 五、强制保护现场

- 保存开始时分支、提交、已有 diff/未跟踪清单；所有练习在独立副本/分支与隔离数据中做。
- 基线失败保留命令与输出，说明与本次变更的关系，不擅自改测试绕过。
- 修复前保留失败证据；改变 schema 前保留隔离快照并验证恢复，不直接覆盖原库。
- 只清理本任务创建且可确认归属的临时文件/进程；不使用破坏性 Git 清理。
