# 项目 01：个人博客

**对应阶段：阶段 03｜建议周期：2–3 周｜类型：前端内容网站**

## 项目目标

实现一个支持 Markdown 内容、标签分类、搜索和响应式阅读的个人博客，证明 React 组件、状态、路由、内容处理和前端测试能力。

## 用户故事

- 访客可以浏览文章列表，并按标签或关键词筛选。
- 访客可以阅读文章详情，查看目录、发布日期和阅读返回位置。
- 访客可以在手机、平板和桌面端舒适阅读。
- 键盘用户可以操作导航、搜索、标签和主题切换。
- 内容缺失或路径错误时，用户能看到明确反馈而非空白页。

## MVP 范围

- [ ] 首页、文章列表、文章详情、标签页、关于页、404。
- [ ] Markdown 本地内容加载，标题、日期、摘要、标签等元数据校验。
- [ ] 搜索、标签筛选、排序；筛选条件可同步到 URL。
- [ ] 响应式导航、代码块、表格、图片和文章目录。
- [ ] 深色/浅色主题，尊重系统偏好并保存用户选择。
- [ ] 基础 SEO 元信息、语义 HTML、焦点管理和减少动态效果支持。
- [ ] 前端测试、生产构建和静态部署。

## 明确不做

- 不做真实评论、用户系统和在线编辑器。
- 不接 CMS、不做后端搜索、不为了博客引入微服务。
- 不直接渲染未经清洗的不可信 HTML；若内容来自外部，必须建立清洗策略。

## 建议数据模型

```ts
type Post = {
  slug: string
  title: string
  summary: string
  publishedAt: string
  tags: string[]
  draft: boolean
  content: string
}
```

类型不能代替运行时校验。构建内容索引时检查重复 slug、非法日期、缺失标题和草稿发布规则。

## 核心实现提示

1. 先用 3 篇真实内容打通列表到详情，再扩展动画与视觉。
2. 将内容解析、筛选排序和 UI 分层，核心函数保持可单测。
3. 搜索处理空关键词、大小写、无结果和特殊字符。
4. 路由切换后处理页面标题、滚动与焦点；深层链接刷新可用。
5. 图片设置尺寸和替代文本；按测量结果处理包体和代码分割。

## 必测场景

- [ ] 正常文章、草稿、无标签、无搜索结果和无效 slug。
- [ ] 重复 slug 与缺失元数据会明确失败，不静默生成错误页面。
- [ ] 搜索与标签组合、URL 恢复和浏览器前进后退。
- [ ] 键盘导航、主题持久化、移动端菜单和焦点。
- [ ] Markdown 中的链接、代码、表格、图片和不可信 HTML。
- [ ] 一条端到端路径：首页 → 筛选 → 阅读 → 返回列表。

## 可访问性验证

以 WCAG 2.2 AA 为参照，保留自动与人工两类证据：

- 对首页、列表、详情和 404 运行 axe 或 Lighthouse，记录工具、日期和结果；serious/critical 问题必须修复或说明阻断原因。
- 仅用键盘完成导航、搜索、筛选、主题切换和移动菜单，检查焦点顺序、焦点可见、Esc 关闭及关闭后的焦点返回。
- 在 200% 缩放和常见窄视口下检查内容不丢失、功能可操作；开启减少动态效果偏好验证非必要动画被减少。
- 自动分数不等于通过；人工未覆盖的读屏、真实用户测试等限制必须写明。

## 验收标准

- [ ] 至少 5 篇有实际内容的示例文章，不全是占位文本。
- [ ] 常见视口无横向溢出，核心交互可仅用键盘完成。
- [ ] 自动可访问性扫描与人工检查均有证据，未覆盖项明确记录。
- [ ] 格式、Lint、类型、单元/组件测试、E2E 和构建实际通过。
- [ ] 部署链接可访问，或提供可复现本地预览；404 与深层路由正确。
- [ ] README 展示架构、内容格式、命令、截图、测试和已知限制。

## 可选扩展（MVP 验收后）

- RSS、sitemap、全文搜索、阅读进度、i18n、静态 OG 图。
- Next.js 重构对比：只在能解释 SSG/SSR/CSR 取舍时进行。
