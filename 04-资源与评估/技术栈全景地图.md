# 全栈技术栈全景地图

> 本图是技术候选地图，不是所有公司官方要求的并集，也不是全部必修清单。默认只有一套主力栈、一套迁移栈与一个岗位专项；实际能力用 [[岗位能力矩阵与验收标准|M/G 验收]] 判定。
>
> 本图覆盖企业应用、互联网服务、跨端开发、云原生、数据与 AI 应用的常见技术生态。目标是“全部纳入长期地图、按层级逐步掌握”，不是在同一时期安装或学习全部工具。

## 一、统一优先级与掌握标准

| 层级 | 定位 | 完成标准 |
| --- | --- | --- |
| **P0 主线** | 第一套独立交付栈与所有全栈底层能力 | 能独立实现、测试、部署、诊断，完成相应 G0–G6 项目关口；完整深度训练还须 G7–G9 |
| **P1 中线** | 第二套生产交付栈与常见企业工程能力 | 能跨栈实现同一业务，解释差异、迁移成本和适用场景 |
| **P2 专项扩展** | 按岗位、项目或兴趣选择的方向 | 至少完成一个专项作品或真实问题验证，不要求全部精通 |
| **P3 前沿/认知** | 需要知道边界、何时使用及如何验证 | 能写技术卡片、做最小实验或比较，不把“听过”标成“掌握” |

学习采用 **1 条主线 + 1 条中线 + N 个专项**。具体时间安排见 [[../03-执行计划/长期学习路线|长期学习路线]]。

## 二、跨技术栈的底层能力

这些能力比框架选择更重要，全部属于长期必修：

| 能力域 | 必学内容 | 验证方式 |
| --- | --- | --- |
| 编程基础 | 类型、值与引用、作用域、模块、错误、并发模型、泛型、内存与资源管理 | 两种语言实现同一模块并比较 |
| 数据结构算法 | 数组、链表、栈、队列、哈希、树、堆、图、排序、搜索、复杂度 | 独立编码、边界测试、复杂度分析 |
| 计算机系统 | 进程、线程、调度、虚拟内存、文件、I/O、系统调用、容器与虚拟机差异 | 用实验观察资源限制和故障 |
| 网络 | TCP/UDP、TLS、DNS、HTTP/1.1/2/3、WebSocket、代理、负载均衡、CDN | 抓包、网络面板、故障复现 |
| 数据原理 | 关系模型、SQL、事务、隔离、锁、索引、复制、分区、备份恢复 | SQL、执行计划、并发与恢复实验 |
| 分布式基础 | 延迟、部分失败、时钟、CAP/PACELC、一致性、幂等、共识和最终一致性 | 故障注入与一致性设计说明 |
| 安全 | 威胁建模、认证授权、密码学使用边界、注入、XSS、CSRF、SSRF、供应链 | 针对性测试与修复证据 |
| 架构与设计 | 模块化、依赖边界、DDD、Clean/Hexagonal、C4、ER、时序图、ADR | 图、代码、决策和演进路径一致 |
| 质量与运维 | 测试策略、性能分析、CI/CD、可观测性、SRE、故障响应和复盘 | 自动化检查、演练与量化报告 |
| 产品与协作 | 需求、用户故事、范围、估算、评审、文档、沟通、隐私与合规意识 | 需求到交付的可追踪记录 |

| 向量检索 | pgvector | Qdrant、Milvus、Weaviate、Elasticsearch 向量能力 | Embedding 维度、召回、过滤、评估、更新与成本 |

## 十、业务与通用非功能能力

以下不属于某个框架，但任何完整全栈计划都应包含：

- **需求与产品**：用户研究、用户故事、验收标准、MVP、领域建模、流程与原型。
- **架构文档**：C4、ER、状态机、时序图、ADR、Runbook、威胁模型。
- **协作交付**：Scrum/Kanban 基础、估算、代码审查、版本策略、CHANGELOG、SemVer。
- **非功能需求**：性能、可靠性、可用性、可访问性、国际化、可维护性、成本和隐私。
- **合规意识**：个人信息保护、数据最小化、保留与删除、审计、Cookie/同意、跨境和许可；具体项目需专业审查。
- **开源与许可证**：依赖许可证、NOTICE、SBOM、贡献流程和供应链风险。
- **运营增长（扩展）**：SEO、Web Analytics、A/B 测试、Feature Flags、反馈与业务指标。
- **故障与沟通**：事件分级、止损、状态同步、无责复盘、行动项跟踪。

## 十一、如何使用这张地图

1. **当前在深度路线的基础阶段（D 周次 / G0–G1）**：只执行 P0；其他技术加入候选，不打断项目。旧“36 周主线”只是 C 索引，不是实际日历。
2. **进入中线**：从 Java/Go/Python 等选择一门有界迁移；JS/TS + Node.js 已计入生产后端技术栈证据，Vue 与企业产品按岗位选用。默认按 [[../01-阶段课程/阶段09-中线技术栈与多语言交付|阶段 09]] 完成 Java/Spring Boot/MySQL 有界交付；只有选择前端迁移时才增加 Vue。
3. **选择专项**：按 [[../01-阶段课程/阶段10-长期扩展与专项深化|阶段 10]] 的入口条件和交付物选择，不要求按表格逐行学习。
4. **每个 P2/P3 技术建立技术卡片**：解决的问题、核心模型、最小示例、测试、成本、替代方案、退出条件。
5. **每季度复审**：依据目标岗位、真实项目和官方维护状态调整层级；记录变更原因，不因短期热度频繁换栈。
6. **淘汰与迁移**：技术退出主线不等于知识作废，保留原理、决策和迁移记录，停止无目的维护旧练习。
