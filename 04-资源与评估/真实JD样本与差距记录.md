## 三、逐份关键要求（原文摘录）

标注规则：**【必需】** 取自“岗位要求/Job qualifications”；**【优先】** 取自原文明确写“优先/加分/Bonus”的条目。未标注者为原文陈述性职责。

### JD-01 腾讯 微信支付-全栈开发工程师（1 年+，深圳）

【必需】
1. 计算机相关专业本科及以上学历，1 年及以上前端开发或 IDE 类产品前端开发经验。
2. 精通 JavaScript/TypeScript，熟悉 React、Vue 等至少一种主流前端框架，掌握常见前端工程化、模块化架构设计。
3. 熟悉面向对象程序设计，能结合复杂富客户端场景进行合理的架构设计和模块划分。
4. 熟悉至少一种主流数据库（如 MySQL、PostgreSQL 等）的使用，具备前端与后端数据交互、接口调优经验。
5. 熟练掌握前端工程化工具，熟悉前端性能优化、兼容性处理、异常监控等核心能力。

【优先】富文本编辑器、游戏开发、渲染引擎开发、跨端开发、IDE 插件、代码编辑器、agent 开发经验；有 AI 辅助开发工具或前端 IDE 类产品经验、参与过相关开源项目。

### JD-02 腾讯 数据中台-全栈开发工程师（1 年+，深圳）

【必需】
1. 计算机相关专业本科及以上学历，1 年以上全栈开发经验。
2. 熟练掌握至少一种后端开发语言（如 Java、Python、Go 等）和一种前端框架（如 React、Vue 等）。
3. 熟悉大数据处理技术栈，如 Hadoop、Spark、Flink、Kafka 等，有实际项目经验。
4. 熟悉关系型数据库（MySQL、PostgreSQL）和 NoSQL（HBase、MongoDB）。
5. 具备良好的系统设计能力，能够独立完成复杂系统的架构设计和开发。
6. 具备 vibe coding 实战经验，掌握如何使用 AI 写出高质量的代码。

【优先】有大数据相关项目经验；云原生（Kubernetes、Docker）与微服务实践；数据治理/数据质量；数据中台、数仓或 BI 经验；Tableau/PowerBI；了解机器学习或 AI。

### JD-03 腾讯 微信支付-全栈开发工程师-基础设施平台（3 年+，深圳）

【必需】
1. 本科及以上，计算机/软件工程/人工智能等相关专业，3 年及以上互联网或金融科技研发经验。
2. 熟练掌握 Go、Python、Node.js 等至少一门后台开发语言，并对相关框架原理有深入理解。
3. 了解大模型相关技术生态，具备大模型应用落地（如 Prompt Engineering、RAG、Agent 开发）的实践经验或浓厚兴趣。
4. 追求极致的系统稳定性和用户体验，具备良好的逻辑思维、风险意识和编码规范。

【优先】AIOps、智能运维平台或大数据处理项目经验；熟悉主流大模型推理优化及部署技术。

### JD-04 腾讯 大数据平台部-全栈开发工程师（3 年+，北京）

【必需】
1. 计算机或相关专业本科及以上学历，具备基本计算机理论基础。
2. 熟悉一种或多种后端编程语言，如 Java、Go、Python 等，具备扎实的工程编码能力。
3. 熟练掌握一种及以上大数据处理或分析框架，如 Spark、Flink、Hive 等，具备海量数据处理经验与一定数据分析能力。
4. 具备良好的沟通协作与问题解决能力，能高效推动跨团队项目落地。

【加分】机器学习、数据挖掘、大模型、推荐、广告、搜索等工程实践；AI Agent 开发或落地经验；画像/标签平台/数据中台建设经验；高并发高可用服务设计经验。

### JD-05 腾讯 微信小程序-前端开发工程师（1 年+，广州）

【必需】
1. 本科及以上学历，计算机相关专业。
2. 掌握计算机学科基础知识，包括但不限于编程、算法、数据结构、网络、web 安全等基础。
3. 前端基础扎实，深入理解前端工程化，包括工程构建、打包、部署，掌握前端优化手段。
4. 至少熟练掌握一种前端框架（React/Vue/…），了解小程序开发和原理。
5. **具备全栈开发知识和能力（如 Node.js 或其他框架/语言）**。

【加分】AI 相关技术研究及实践经验；有开源项目贡献经历。

### JD-06 腾讯 微信小店-全栈开发工程师-交易基建（1 年+，广州）

【必需】
1. 至少 1 年以上全栈开发经验，具备扎实的代码、算法和数据结构基础。
2. 逻辑思维清晰，有责任心，对技术保持探索和热情。
3. 熟练掌握至少一套前端开发框架（Vue/React）和 Node.js 服务端框架（Express/Koa/Nestjs），并了解其工作原理。
4. 了解全栈开发流程，包括前端工程化、服务部署、监控等全流程。
5. 了解 AI Agent 工作原理。

【优先】有 AI Agent 研发经验者。

职责原文：负责电商相关基建的开发工作，涵盖客服、售后、物流等模块；主动推动团队技术基建的持续迭代和优化，完善团队 AI Agent 基建，提升团队研效。

## 四、样本内频次（分母 8，仅描述本样本）

分母是 8：JD-01–06、JD-09、JD-10 这 8 份有任职要求；JD-07、JD-08 只有列表页职责，不计入。

| 要求 | 出现份数 | 出现在 |
| --- | --- | --- |
| 至少一门编程语言（JS/TS/Java/Go/Python/Node 等） | 8/8 | 全部有要求的样本 |
| 本科及以上 / 计算机相关专业 | 5/8 | JD-01–05 |
| 前端框架（React 或 Vue 至少一种） | 5/8 | JD-01、02、05、06、09（JD-09 原文把 React 列在“语言”清单里） |
| 前端工程化 / CI-CD / TDD 实践 | 5/8 | JD-01、05、06、09、10 |
| 系统设计与架构能力 | 3/8 | JD-01、02、10 |
| 性能优化与稳定性 | 3/8 | JD-01、03、05 |
| AI 能力为必需（含“了解 Agent 工作原理”“浓厚兴趣”） | 3/8 | JD-02（用 AI 写高质量代码）、JD-03（Prompt/RAG/Agent）、JD-06（了解 AI Agent 原理） |
| Node.js 服务端（框架或全栈能力） | 2/8 | JD-05（具备全栈知识如 Node.js）、JD-06（Express/Koa/Nestjs） |
| 数据库（MySQL/PostgreSQL/NoSQL） | 2/8 | JD-01、02 |
| 大数据栈（Spark/Flink/Hive/Kafka） | 2/8 | JD-02、04 |
| 英语可作为工作语言 | 1/8 | JD-09（Must have） |

另计“优先/加分”而非必需：AWS/Docker/K8s 2 处（JD-09、JD-10）、AI 相关 4 处（JD-01、04、05、06）。

结论只限三条，不外推：

1. **语言 8/8、框架 5/8** 是这份样本里最稳的门槛；只学框架不学语言基础，在 JD-05、JD-09 这类岗位会被直接筛掉。
2. **“全栈”在本样本里不等于“前后端都精通”**：JD-01 要前端深度 + 数据库/接口调优；JD-06 要 Vue/React + Node.js 服务端框架 + 部署监控；JD-02、04 要后端 + 大数据；JD-05 前端为主但明确写“具备全栈开发知识（如 Node.js）”。
3. **AI 已从纯加分变成三分之一岗位的必需项**：JD-02 把“用 AI 写高质量代码”写进要求，JD-03 要求大模型应用实践或浓厚兴趣，JD-06 要求“了解 AI Agent 工作原理”；另有 4 处列为优先。把 AI 只当“扩展话题”会与这批 JD 脱节。

## 五、差距映射

对照 [[岗位能力矩阵与验收标准|岗位能力矩阵]] 的 M 编号，只列本样本反复出现的项：

| 要求 | 对应模块 | 课程位置 | 当前证据 | 差距与最小补强 |
| --- | --- | --- | --- | --- |
| 语言 + 类型 + 框架 | M03 / M05 | 阶段 02、03 | 待学习者填写 | 用项目 01/02 的组件与 API 代码作为证据；无可运行仓库时记“未评估” |

| 服务部署与监控 | M09 / M11 | 阶段 07 | 待学习者填写 | JD-06 把“服务部署、监控”写进全栈流程；需要一次真实的部署 + 告警/日志排障记录 |
| 系统设计与架构表达 | M10 | 阶段 07、项目 04 | 待学习者填写 | 补一份含容量估算与取舍的架构文档，而非只画框图 |
| 数据库与接口调优 | M06 | 阶段 05 | 待学习者填写 | 需要执行计划、索引前后对比、慢查询定位的真实记录 |
| 工程化 / CI-CD / TDD | M07 / M08 | 阶段 06、07 | 待学习者填写 | 流水线要能展示失败阻断与回滚，不只截一张绿灯图 |
| 性能与稳定性 | M09 | 阶段 06、07 | 待学习者填写 | 同口径压测 + 至少两类故障注入 + 恢复记录 |
| 大数据栈（Spark/Flink） | M13 扩展 | 阶段 10 | 待学习者填写 | 仅在目标 JD 明确要求时补；不做全库必修 |
| 大模型应用（Prompt/RAG/Agent） | M14 | 阶段 10、项目 04 | 待学习者填写 | 需 golden set + 引用与拒答指标，不能只演示对话 |

“待学习者填写”不是遗漏，而是本库不能代替学习者生成证据；填之前状态一律为**未评估**。

## 六、复测与失效处理

- 复测频率：每 3 个月或投递前各复核一次，先看页面是否仍在线、经验年限与要求是否变化。
- 已失效样本（腾讯 游可爱-AI全栈，JD 详情页返回空壳）保留在清单中并标注失效，不删除、不替换成别的岗位。
- 只有职责、没有要求的 2 条（JD-07、JD-08）在补到美团单岗详情页前不参与统计；补齐后需重算第四节频次（分母将变为 10）。
- 新增样本仍按本文件格式记录，禁止把第三方招聘平台或博客转述当作官方原文。
