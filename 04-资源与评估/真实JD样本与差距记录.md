【加分】有完整全栈项目经验，能独立完成从页面、接口、数据到部署验证的端到端交付；有 LangChain/Eino 等 AI 框架深度使用经验，或有 AI 评测体系建设经验；有 C 端 AI 业务落地场景、参与或主导过优秀开源项目、有技术博客产出。

> JD-12 的“前端工程化、性能监控、高可用”写在**职位描述**里、“页面→接口→数据→部署验证”写在**加分项**里，按本文件计数规则均不计入必需频次。

结论只限三条，不外推：

1. **语言 12/12、学历 9/12** 是这份样本里最稳的门槛；明确要求 React/Vue 的只有 5/12，集中在全栈/前端岗——JD-03、04、09、10、11 都不要求前端框架，JD-07 写的是“前端或后端框架之一”。**“全栈”不等于“必须会 React/Vue”**，把多选一当必要条件会高估前端框架的权重。
2. **“全栈”在本样本里有四种写法**：JD-06 是唯一**强制** Node.js 服务端框架的岗位（Express/Koa/Nestjs + 前端框架 + 工作原理），JD-11 是 Java 为主 + App/H5 + 上线验证，JD-12 是前端偏重 + 后端概念 + AI 能力，JD-01 是前端纵深 + 数据库/接口调优。Node 在另外 4 份里只是“可选后端之一”，所以 Node 必须练到能讲清原理，但不要据此推断所有全栈岗都以 Node 为主。
3. **AI 已进入 7/12 岗位的必需项，另有 9 处加分**：必需侧写法是“用 AI 写高质量代码 / AI Coding 完成交付上线 / Prompt·RAG·Agent 实践”，加分侧是“AI 工具与 Agent 研发经验”。把 AI 只当扩展话题会与一半以上样本脱节。

## 六、复测与失效处理

- 复测频率：每 3 个月或投递前各复核一次，先看页面是否仍在线、经验年限与要求是否变化。
- 已关闭样本 D-01 保留为补充记录并标注“当前职位无法投递”，要求原文继续作为岗位标准证据，但不得写成“在招”，也不得替代 JD-08。
- JD-07（`4697320043`）、JD-08（`4697318475`）以官方 `jobUnionId` 直链复核；岗位若重发会更换 ID，届时按检索重新定位并更新清单，**不得凭记忆填写 ID**。
- 新增样本仍按本文件格式记录；禁止把第三方招聘平台、转载站或博客转述当作官方原文。
- 计数规则变更（新增/删除样本、调整必需口径）必须整表重算，不得在旧数字上增减。
