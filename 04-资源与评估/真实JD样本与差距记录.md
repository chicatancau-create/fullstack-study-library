| 性能优化与稳定性 | **3/12** | JD-01、03、11 |
| 端到端交付 / 上线验证 | **3/12** | JD-06、08、11 |
| 数据库（MySQL/PostgreSQL/NoSQL） | **3/12** | JD-01、02、12 |
| 大数据栈（Spark/Flink/Hive/Kafka） | **2/12** | JD-02、04 |
| 英语可作为工作语言 | **1/12** | JD-09（Must have） |

**加分 / 优先项全量枚举（不计入上表）**

| 类别 | 处数 | 出现在 |
| --- | --- | --- |
| AI 相关（AI 工具经验、Agent 研发、AI 应用 0→1、AI 框架/评测） | **9** | JD-01、02、03、04、05、06、07、08、12 |
| 云原生（Kubernetes / Docker / 云平台） | **3** | JD-02（Kubernetes、Docker 与微服务）、JD-09（AWS/Docker/K8s）、JD-10（AWS/Azure/K8s/Docker） |
| 端到端交付 | **1** | JD-12（加分项） |
| 开源 / 技术博客 / 社区分享 | **4** | JD-01、05、10、12 |
| 大数据与数据治理（加分侧） | **2** | JD-02、04 |

结论只限三条，不外推：

1. **语言 12/12、学历 9/12** 是这份样本里最稳的门槛；框架 6/12 集中在全栈/前端岗——JD-03、04、09、10、11 都不要求前端框架（JD-09 把 React 列在“语言”清单里，不是框架要求）。
2. **“全栈”在本样本里有四种写法**：JD-06 是 Node.js 全栈（Express/Koa/Nestjs + 前端框架），JD-11 是 Java 为主 + App/H5 + 上线验证，JD-12 是前端偏重 + 后端概念 + AI 能力，JD-01 是前端纵深 + 数据库/接口调优。只练一种组合会在另外三种上失分。
3. **AI 已进入 7/12 岗位的必需项，另有 9 处加分**：必需侧写法是“用 AI 写高质量代码 / AI Coding 完成交付上线 / Prompt·RAG·Agent 实践”，加分侧是“AI 工具与 Agent 研发经验”。把 AI 只当扩展话题会与一半以上样本脱节。

## 五、差距映射

对照 [[岗位能力矩阵与验收标准|岗位能力矩阵]] 的 M 编号，只列本样本反复出现的项：

| 要求 | 对应模块 | 课程位置 | 当前证据 | 差距与最小补强 |
| --- | --- | --- | --- | --- |
| 语言 + 类型 + 框架 | M03 / M05 | 阶段 02、03 | 待学习者填写 | 用项目 01/02 的组件与 API 代码作为证据；无可运行仓库时记“未评估” |
| Node.js 服务端与框架原理 | M04 | 阶段 04 | 待学习者填写 | JD-06 明确要 Express/Koa/Nest 之一并“了解工作原理”，需能解释中间件、路由、错误处理链路 |
| 服务部署与监控 | M09 / M11 | 阶段 07 | 待学习者填写 | JD-06 把“服务部署、监控”写进全栈流程；需要一次真实的部署 + 告警/日志排障记录 |
| 端到端交付 | M11 | 项目 02–04 | 待学习者填写 | JD-11 要求「方案设计 → 后端 → App/H5 → 上线验证」闭环；JD-08 要求“完成功能交付上线”，需一次完整交付记录而非分段截图 |
| 系统设计与架构表达 | M10 | 阶段 07、项目 04 | 待学习者填写 | 补一份含容量估算与取舍的架构文档，而非只画框图 |
| 数据库与接口调优 | M06 | 阶段 05 | 待学习者填写 | 需要执行计划、索引前后对比、慢查询定位的真实记录 |
| 工程化 / CI-CD / TDD | M07 / M08 | 阶段 06、07 | 待学习者填写 | 流水线要能展示失败阻断与回滚，不只截一张绿灯图 |
| 性能与稳定性 | M09 | 阶段 06、07 | 待学习者填写 | 同口径压测 + 至少两类故障注入 + 恢复记录 |
| 大模型应用（Prompt/RAG/Agent） | M14 | 阶段 10、项目 04 | 待学习者填写 | 需 golden set + 引用与拒答指标，不能只演示对话 |
| 大数据栈（Spark/Flink） | M13 扩展 | 阶段 10 | 待学习者填写 | 仅在目标 JD 明确要求时补；不做全库必修 |
| 英语工作能力 | 通用 | 官方文档阅读 | 待学习者填写 | 用英文官方文档阅读记录与英文项目 README 作证据 |

“待学习者填写”不是遗漏，而是本库不能代替学习者生成证据；填之前状态一律为**未评估**。

## 六、复测与失效处理

- 复测频率：每 3 个月或投递前各复核一次，先看页面是否仍在线、经验年限与要求是否变化。
- 已关闭样本 D-01 保留为补充记录并标注“当前职位无法投递”，要求原文继续作为岗位标准证据，但不得写成“在招”，也不得替代 JD-08。
- JD-07、JD-08 的详情页 URL 属 SPA 客户端路由，未取得稳定锚点：每次复测须重新走官方站内检索定位，若届时有稳定 `jobUnionId` 再补入清单，**不得凭记忆填写 ID**。
- 新增样本仍按本文件格式记录；禁止把第三方招聘平台、转载站或博客转述当作官方原文。
- 计数规则变更（新增/删除样本、调整必需口径）必须整表重算，不得在旧数字上增减。
