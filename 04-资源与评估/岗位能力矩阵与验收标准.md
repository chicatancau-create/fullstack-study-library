# 岗位能力矩阵与验收标准

> 这是课程设计的通用能力模型，不是任何公司的官方招聘标准，未声称逐条核验所有公司的当前 JD。公司、职级、国家和业务差异通过末尾 JD 差距表处理。

## 一、能力判定

0 = 未接触；1 = 能解释；2 = 在教程/明确提示下实现；3 = 面对未见过的有界任务，能独立实现、测试并解释；4 = 能诊断故障、比较方案、迁移约束并完成可复核交接。指导他人可作为补充证据，但不是所有主修域的统一硬门槛。

无实际实现与测试证据最高 2 分。有自己生成的代码但不能独立解释，仍不记 3 分。4 分不等于公司高级职级，也不能凭一次顺利演示获得整个领域的 4 分。

“共通”表示课程的基础能力要求；“主修”表示当前职业重点；“岗位专项”仅对选定方向强制。低层知识须知道适用边界，不能把一个实现的机制误当成所有语言或数据库的行为。

| M12 发布与可靠性 | 不可变制品、兼容迁移、SLI/SLO、错误预算、RPO/RTO | 干净部署、兼容发布、回滚/恢复、一次告警到 Runbook 闭环 | E13、CI/演练/原始输出；G5/G6 |

深度路线最终要求 M01–M15 均达到 3；与选定主修相关的至少三个能力域达到 4，并分别有机制实验、诊断/取舍和迁移证据。具体字段级核对用 [[能力自检清单|能力自检清单]]；最终实操仍须单独通过。各语言按 [[../01-阶段课程/专项-多语言知识树与课程导航|多语言知识树]] 补充执行模型、类型、资源、并发、I/O、测试与诊断证据，不能只凭框架作品评分。

## 三、岗位专项：选一个深入

| 方向 | 必须深挖 | 验收作品与失败场景 | 不自动要求 |
| --- | --- | --- | --- |
| 前端 / 全栈偏前端 | 浏览器/JS、React、构建、SSR/SSG、缓存、组件系统、可访问性、体验监控 | 可复用组件或复杂页面 + hydration/缓存泄漏/大列表实验 + 弱网与性能报告 | 多种 UI 框架全部熟练、K8s 集群管理 |
| Java / 全栈偏业务后端 | Java/JMM/JVM、Spring 事务/安全、MySQL、MQ、缓存与可靠事件 | JVM/锁或连接池诊断 + Outbox/幂等/对账 + 兼容迁移 | Seata、Nacos、Sentinel 等每种产品都上 |
| Go / 服务与平台 | context/并发/GC、网络、背压、竞态、gRPC/契约 | 有界调度器或服务 + race/pprof + 取消/过载/泄漏验证 | 学完所有云厂商与服务网格 |
| SRE / 平台 | Linux/网络、容器/K8s、IaC、CI/CD、SLI/SLO、容量/成本 | 可重复环境 + 漂移/回滚 + 告警/演练 + 值班 Runbook | 仅以安装大量平台作为作品 |
| 数据 / AI 应用 | Python/异步、数据质量、检索评测、权限、工具约束与成本 | 版本化评估集、训练/调参/测试隔离、引用/拒答、跨租户检索与注入测试 | 用聊天界面代替评估，基础模型训练默认必修 |
| 鸿蒙 / 客户端跨端 | ArkTS/ArkUI、Stage/UIAbility、导航/生命周期、ArkData、权限、并发、Hvigor 与签名 | [[../01-阶段课程/专项-鸿蒙ArkTS与ArkUI应用开发\|鸿蒙应用]] + 离线/权限拒绝/进程重建测试 + 性能与真机/发布证据 | 仅凭预览器截图宣称真机、跨设备或上架通过；同时主学多套移动框架 |
| uni-app / Vue 跨端 | Vue 3、uni-app/uni-app x 边界、条件编译、应用/页面/组件生命周期、原生能力与各端发布 | [[../01-阶段课程/专项-uni-app跨端应用开发\|uni-app 作品]] + ≥2 目标端真实构建 + 权限/离线/重复提交测试；只有两端真机实测才可写“双端真机通过” | 用 ArkTS/Hvigor 验收 uni-app；用 H5 或模拟器截图宣称全端；混淆 uni-app 与 uni-app x |

选定专项后将其三个核心域作为 4 分候选；未测量的部分仍按实际评分。算法/推荐、客户端、内核、数据库内核、音视频等专门岗位，还需相应数学/系统/领域课程，本计划的应用研发主线不足以宣称匹配。

## 四、层级判断

- 入门可交付：完成 G0–G4，尚不能宣称已通过全部深度训练。
- 应用研发上岗准备：全部共通项、选定主修、项目 05 与 G9 实操通过，并完成目标 JD 核对。
- 独立复杂模块：在上述基础上持续维护、处理真实变更，交付与运行结果由团队验证。
- 资深/专家/负责人：需真实规模、组织影响、长期维护与带队证据；不由课程时长或毕业标签授予。
