# 专项：多语言知识树与课程导航

**定位：当前计划内所有语言/标记与查询语言的统一入口｜原则：先理解计算与资源模型，再学语法、生态和框架。**

> 本导航追求“知识维度不漏项”，不声称替代任何语言的全部标准库、API 或版本变更。每门语言按 P0–P3 控制深度；同一知识在不同语言中比较，不把“读过语法”登记为掌握。

## 一、第一性原理：任何语言都回答十二个问题

1. **程序如何执行**：源码、解释、JIT、AOT、字节码、虚拟机和入口是什么？
2. **值如何表示**：基本值、对象、可空性、相等、可变性、精度、编码和时间如何定义？
3. **类型何时生效**：静态/动态、强/弱、推断、泛型、转换，以及运行时边界在哪里？
4. **计算如何组合**：表达式、控制流、函数、闭包、模块、抽象和依赖方向如何工作？
5. **数据如何组织**：数组、字符串、映射、集合、树、流和自定义数据结构有何复杂度？
6. **错误如何传播**：返回值、异常、Result、错误码、取消、回滚和失败安全如何实现？
7. **资源由谁负责**：内存、文件、连接、锁、句柄和生命周期由谁创建、共享与释放？
8. **并发如何发生**：进程、线程、事件循环、协程、通道、共享内存、可见性和背压如何协调？
9. **外部世界如何交互**：文件、网络、数据库、系统调用、序列化和不可信输入如何处理？
10. **正确性如何证明**：测试、类型、断言、属性、形式化约束、调试和回归如何组合？
11. **性能如何测量**：复杂度、分配、缓存、JIT/GC、系统调用、网络和 P95/P99 如何定位？
12. **系统如何交付**：依赖、构建、兼容、秘密、安全、部署、观测、升级和维护如何闭环？

学习任何语言都按“解释机制 → 最小实现 → 构造反例 → 测量诊断 → 新约束迁移”执行。只覆盖第 1–5 项属于语法入门，不能标记为生产掌握。

## 二、统一验收等级

| 等级 | 必须回答 | 证据 |
| --- | --- | --- |
| L1 会语法 | 值、类型、控制流、函数、容器和基本错误如何处理 | 最小程序、边界测试、官方文档核对 |
| L2 能生产 | 模块、依赖、I/O、资源、错误、测试、部署如何形成闭环 | 有边界的服务/工具、CI、README、故障处理 |
| L3 懂运行时 | 执行、内存、调度、并发、GC/所有权和性能如何诊断 | Profiler、转储、竞态/泄漏实验、优化报告 |
| L4 能设计 | 语言与生态为何适合该约束，替代方案和维护成本是什么 | ADR、同口径对照、迁移与回滚方案 |

## 四、运行时不是独立语言

| 运行时 | 教学入口 | 必须区分 |

| Node.js | [[专项-运行时-NodeBunDeno\|Node、Bun、Deno：JS/TS 运行时比较]] | V8、libuv、事件循环、npm 与生产部署 |

Node 已计入一门生产后端语言。比较运行时只在同一业务、同一依赖能力、同一硬件与同口径测试下进行，不能靠 Hello World 排名。

## 五、每门语言的标准教学结构

所有语言文档尽量保持以下顺序，便于逐条复核：

1. 执行模型与适用边界；
2. 值、类型、求值和可变性；
3. 函数、控制流、数据结构与抽象；
4. 错误、资源与生命周期；
5. 模块、依赖与构建；
6. 并发、I/O 与外部系统；
7. 测试、调试、性能与安全；
8. 最小实验、深度实验和验收；
9. 版本差异与常见误区。

语言没有某特性时，应写“该语言用什么替代模型”，而不是留空。例如 C 没有异常和 GC，就检查返回值与手动资源释放；SQL 没有通用函数式应用结构，就检查声明式查询、约束、事务与执行计划。

## 六、执行规则

- P0 语言完成对应最小实验；P1 选择一门迁移语言到 L2/L3；P2 只按岗位方向深入；P3 至少能写技术卡片与最小反例。
- 每门语言至少一个失败实验：内存/类型错误、竞态、资源泄漏、解析失败、权限拒绝、性能退化或兼容问题。
- 任何性能结论记录版本、实现、硬件、数据、参数和原始输出；没有测量时只做定性说明。
- 文档详细不等于学习完成。真实掌握仍以可运行代码、测试、诊断和迁移证据为准。
