## 1. 关系模型与执行边界

- SQL 是声明式查询语言：描述需要的结果，由数据库优化器选择执行路径，不是逐行脚本。
- 关系模型以集合/关系为数学基础，但 SQL 表与查询结果默认具有**多重集（bag/multiset）语义**，可以包含重复行，不等于数学集合。需要去重时显式使用 `DISTINCT`、`UNION` 或合适的分组。
- `UNION` 默认去重并可能产生排序/哈希成本，`UNION ALL` 保留重复且通常更便宜；二者不是性能写法的小差异，而是结果语义不同。
- 连接会使匹配行数相乘；一对多或多对多连接后不要假设结果行数与任一输入相同。聚合前先确认粒度，避免重复计数。
- 列有域与约束；主键、候选键、外键和关系完整性先于 ORM。
- 逻辑查询顺序与物理执行顺序不同；优化器会重写，不能按 SQL 文本猜性能。
- PostgreSQL/MySQL/SQLite 在类型、NULL、唯一、锁、隔离、DDL 和函数上有差异，所有实验注明数据库与版本。

## 2. 值、类型与 NULL 三值逻辑

- 整数、定点、浮点、文本、布尔、日期时间与 JSON 的选择；金额避免二进制浮点。
- NULL 表示缺失/未知，不等于 0、空串或 false；比较使用 `IS NULL`。
- `NOT IN` 子查询遇 NULL 可能产生反直觉结果，理解 TRUE/FALSE/UNKNOWN 与 EXISTS。
- 字符集、 collation、大小写、尾随空格、时区和 UTC 存储/显示边界。
- CHECK、NOT NULL、UNIQUE、FK 将不变量落入数据库，但唯一约束中的 NULL 行为按数据库核对。

## 3. 查询与集合操作

- SELECT/WHERE/JOIN/GROUP BY/HAVING/ORDER BY/LIMIT 的逻辑含义。
- INNER/LEFT/ANTI/SEMI JOIN，连接条件与 WHERE 对左连接的不同影响。
- GROUP BY 的键、聚合和重复计数；不要依赖非标准宽松分组。
- UNION/UNION ALL/INTERSECT/EXCEPT 的集合语义与去重成本。
- CTE、子查询、窗口函数、分区、排序、frame 和 Top-N/连续行为。
- 稳定分页必须唯一排序；offset 大页、keyset 游标和并发数据变化各有边界。

## 4. 数据建模与变更

- 1:1、1:N、M:N、快照、审计、状态历史和多租户归属。
- 规范化减少更新异常；反规范化需写清一致性来源、更新路径和收益。
- 事务中的 DDL/DML、默认值、生成列和约束延迟按数据库验证。
- UPSERT/MERGE 不是天然幂等；并发唯一冲突与重试必须设计。
- 迁移要可重复审查、向前兼容、可恢复， destructive 操作有备份与分批方案。

## 5. 事务、隔离与并发

- ACID 的实际含义；原子性不代表所有外部副作用回滚。
- 脏读、不可重复读、幻读、写偏差、丢失更新和序列化异常。
- MVCC 快照、当前读/锁读、行锁/表锁/间隙锁按数据库区分。
- 乐观/悲观并发控制、唯一约束和幂等表；应用重试不能破坏业务不变量。
- 死锁检测、锁等待、短事务和固定访问顺序；长事务会扩大冲突与复制延迟。

## 6. 索引与执行计划

- B+Tree、复合索引最左前缀、覆盖索引、回表、选择性与排序。
- 部分/表达式/全文索引按数据库与查询需求选择，不是越多越好。
- EXPLAIN 与 EXPLAIN ANALYZE 的区别；估算行数、实际行数、扫描、join、sort、buffer 和耗时。
- N+1、隐式转换、函数包裹列、低选择性 LIKE、巨量 IN 和深分页。
- 统计信息、缓存冷热、数据量和参数影响计划；优化后必须回归正确性。

## 7. 安全、测试与运维

- 始终使用参数化查询；标识符白名单，不把表名/列名直接拼接用户输入。
- 数据库账号最小权限，迁移账号与运行账号分离；错误不泄露 SQL/敏感数据。
- 测试覆盖约束、回滚、并发交错、死锁和恢复，不只测查询结果。
- 备份与 binlog/WAL、恢复、时间点恢复和副本一致性按数据库验证。
- 慢查询、连接池、锁等待、缓存失效和复制延迟纳入监控。

## 9. 常见误区

- 把 ORM 当 SQL 黑盒，不看生成查询与事务边界。
- 认为 SERIALIZABLE 或分布式锁可以替代所有业务约束。
- 只看索引数量，不看选择性、写入成本和实际计划。
- 在数据库之间复用测试结论，忽略方言和锁差异。
- 用生产数据直接练习迁移/恢复，或把备份成功当恢复成功。
