## 阶段目标

- 能从状态和交互出发设计组件，而非机械拆分页面。
- 能管理服务端状态、表单、路由和异步边界，并处理失败与空状态。
- 完成 [[../02-项目实战/项目01-个人博客|项目 01：个人博客]]。

## 学习清单

### React 核心

- [ ] 组件、props、state、事件、条件渲染和列表 key。
- [ ] 渲染是纯计算；state 是快照；批处理和不可变更新。
- [ ] 状态提升、状态下沉、派生状态和单一事实来源。
- [ ] `useEffect` 的同步职责、依赖、清理与竞态；不把 Effect 当万能生命周期。
- [ ] `useRef/useMemo/useCallback` 的适用边界，不提前微优化。
- [ ] Context、组合、children 和自定义 Hook；避免深层 prop drilling 与全局状态膨胀。
- [ ] Error Boundary、Suspense 的概念与使用边界。

### 应用能力

- [ ] React Router：嵌套路由、参数、404、导航和滚动/焦点处理。
- [ ] 受控表单、非受控表单、校验、提交中、重复提交和错误反馈。
- [ ] 服务端状态：缓存、失效、重试、取消、分页、乐观更新及回滚。
- [ ] UI 状态与服务端状态分离；不把所有响应复制进本地 state。
- [ ] 设计加载、空、错误、部分成功、离线和权限不足状态。
- [ ] Modal、Toast、Tabs、Combobox 等组件的键盘与焦点管理。

### 样式、质量与构建

- [ ] CSS Modules 或项目既有方案；设计变量、主题与响应式约束。
- [ ] 组件 API、目录边界、公共组件与业务组件的区别。
- [ ] Vite 的开发服务器、环境变量、构建和静态资源处理。
- [ ] Vitest + Testing Library：按用户行为测试，避免测试实现细节。
- [ ] MSW 或等价方式模拟网络；覆盖延迟、失败、空响应和异常数据。
- [ ] Playwright 验证登录外的一条核心用户路径（项目 01 可用发布/阅读路径）。
- [ ] 使用 Lighthouse 和 React 开发者工具发现问题，以测量结果决定优化。

## 最小实践

除项目 01 外，完成三个独立练习：

1. 可搜索、筛选、分页的数据列表，处理 URL 同步和请求竞态。
2. 具备草稿、校验、提交失败恢复和防重复提交的表单。
3. 一个可复用 Dialog，支持 Escape、焦点圈定、关闭后焦点恢复和语义属性。

## 阶段验收

- [ ] 能解释一次输入触发渲染、提交和 Effect 清理的过程。
- [ ] 删除 Effect 后仍能实现的派生状态或事件逻辑，没有滥用 Effect。
- [ ] 核心流程具备加载、空、错误、成功状态，网络失败不会形成空白页。
- [ ] 组件测试与至少一条浏览器测试真实执行通过。
- [ ] 构建成功，部署后的深层路由刷新和静态资源路径可用。
- [ ] 项目 README 包含截图、架构、命令、取舍、测试证据和已知限制。

## 常见误区

- 一开始就引入大型状态库、UI 库和请求库，无法解释各自解决的问题。
- 只测试组件是否渲染，没有验证用户可观察行为。
- 只优化渲染次数，不处理包体、图片、网络、缓存和主线程长任务。

## 深度验收（G3，G6/岗位专项加深）

完成 [[专项-核心原理与深度实验|E03/E05]]：确定性请求竞态、乐观回滚、生产产物/缓存失配、CSR 与 SSG/SSR 最小对照。先学 React，再深入元框架，不同时铺开多个框架。SSR/共享缓存要测试个性化数据隔离，前端环境变量不能保存秘密。

可访问性除自动扫描、键盘和 200% 缩放外，还应检查适用的 WCAG 2.2 AA 重排准则（400% 缩放或等效 320 CSS px）、读屏抽测和错误恢复；记录例外及未覆盖范围，不把工具零告警当作完全符合。
