# 语言专项：PHP——请求模型与现代 Web

**层级：P1 按岗位/P3｜目标：默认 L1；存量 Web/Laravel 岗位进入 L2。**

## 1. 执行模型与边界

- PHP 常用于 Web 请求生命周期，PHP-FPM/Apache/CLI 的进程、配置和持久状态不同。
- 典型请求间共享少于长期驻留服务，但 OPcache、连接池、静态状态和队列 Worker 会改变资源模型。
- 现代 PHP 具备类型、属性、枚举、JIT 等能力，不能按早期“只有松散脚本”理解。
- 版本差异显著，旧教程中的 mysql_*、魔术引号、注册全局变量等不应进入现代项目。

## 2. 值、类型与比较

- 动态类型、`declare(strict_types=1)`、参数/返回/属性类型和联合类型。
- `==/===`、类型 juggling、truthy/falsy、null/空数组/空串/"0" 的差异。
- PHP array 同时包含有序列表与映射，键转换、引用和复制语义需要明确。
- 字符串字节与编码、JSON 错误、整数精度和浮点边界。
- 对象句柄、引用赋值和可变状态；避免无意的共享引用。

## 3. 函数、类与抽象

- 命名参数、闭包、箭头函数、静态/实例方法和构造器属性提升。
- 封装、接口、trait、继承与组合；trait 不是无成本模块替代。
- 枚举、只读属性、match 和属性注解按版本使用。
- 异常、Error/Throwable、错误报告和生产环境显示设置；不吞异常或暴露堆栈。

## 4. 请求、状态与安全

- GET/POST/FILES/COOKIE/SESSION/SERVER 都是不可信输入，按来源和结构校验。
- Session Cookie 的 HttpOnly/Secure/SameSite、固定会话、注销和权限更新。
- SQL 使用 PDO 预处理；输出 HTML 按上下文转义，上传检查内容/大小/路径和访问权限。
- CSRF、XSS、SSRF、开放重定向、文件包含和命令注入分别验证。
- `include/require` 的路径和自动加载边界，不能包含用户控制文件。
- 密码使用当前官方哈希 API，秘密和 phpinfo/错误页面不公开。

## 5. Composer、框架与任务

- Composer 依赖、autoload、lock、平台要求和脚本权限。
- PSR 自动加载/编码/HTTP 等规范用于互操作，不等于所有包安全。
- Laravel 的容器、路由、中间件、Eloquent、迁移、队列和调度；框架功能不能代替业务不变量。
- 队列 Worker 长期运行，需处理内存、超时、重试、幂等、失败和关闭。
- OPcache/JIT/预加载和配置按环境验证，不用开发配置推断生产性能。

## 6. 测试、性能与维护

- PHPUnit/Pest 覆盖模型、请求、权限和异常；数据库迁移使用隔离环境。
- Laravel Feature test 验证中间件与响应，但不能替代浏览器和真实队列。
- Xdebug 用于调试/覆盖，生产性能用合适的 Profiler/日志/指标，不让调试器长期暴露。
- 处理 N+1、对象 hydration、序列化、连接和缓存；比较冷/热 OPcache。
- 存量改造先补字符编码、依赖、入口、安全和回归，再逐步升级。

## 7. 教学项目与验收

### 项目

实现一个小型任务 Web 模块：

- Composer 自动加载、环境配置、PDO 迁移和参数化查询。
- 登录/会话、资源授权、CSRF 和输出转义。
- 表单失败、重复提交、上传/错误日志按范围验证。
- 一个幂等队列任务，覆盖失败重试与关闭。

### 通过标准

- [ ] 能解释严格比较、数组/引用和请求输入边界。
- [ ] 能说明请求与长期 Worker 的生命周期差异。
- [ ] 权限、CSRF、SQL 注入和上传至少有针对性测试。
- [ ] Composer 环境可复现，队列失败可恢复。
- [ ] 能阅读并安全修改一个存量模块，而非只会新脚手架。

## 8. 常见误区

- 用宽松比较判断权限、金额或空值。
- 直接拼接 SQL/HTML/文件路径，依赖框架默认配置兜底。
- 把 PHP-FPM 的请求模型套到长期 Worker，导致内存和状态失控。
- 只看页面成功，忽略队列、Session 和 OPcache 环境。
- 复制旧教程函数与配置，未核对当前 PHP 支持状态。
