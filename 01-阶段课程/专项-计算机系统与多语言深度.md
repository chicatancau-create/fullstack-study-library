# 专项：计算机系统与多语言深度

> 排期口径：本页原第 1–52 周属于 C 压缩主题索引；深度路线实际日期与关口以 [[../03-执行计划/深度路线与工时预算|D01–D96 / G0–G9]] 为准。核心实验可复用项目证据，算法与实验工时已计入总预算。

**定位：大厂技术底座｜优先级：P0 基础 + P1 生产语言 + P2 方向语言｜前置：能写基础程序与测试。**

> 多语言目标不是同时精通所有语言，而是形成“底层可迁移、主力能诊断、第二语言能生产、其他语言能阅读”的结构。每个语言级别必须有代码与实验，不能用安装环境或语法清单代替。

## 一、统一深度等级

> 编号约定：本文及语言专项使用 `LANG-L1`–`LANG-L4`；算法专项的等级使用 `ALG-L1`–`ALG-L4`。旧笔记中未加前缀的 L1–L4 保留原含义：算法上下文映射为 ALG-L*，语言上下文映射为 LANG-L*。

| 等级 | 能力定义 | 最低证据 |
| --- | --- | --- |
| L1 会语法 | 能读代码、写小程序、理解错误 | 最小项目与边界测试 |
| L2 能生产 | 能完成模块、并发/错误处理、测试和部署 | 服务、CI、README、故障处理 |
| L3 懂运行时 | 能解释内存、调度、GC/资源、I/O 并诊断性能 | Profiler、竞态/泄漏实验、优化报告 |
| L4 能设计 | 能比较语言与生态，设计模块并说明成本 | ADR、基准、演进与回滚方案 |

最终结构：

- **TypeScript/JavaScript**：主修运行时目标 L3；**SQL** 用建模/查询/事务/诊断证据验收；**C** 完成系统实验与资源错误定位，不要求所有 Web 岗位达到 C 专家水平。
- **JS/TS + Node.js 已计入生产后端技术栈证据**：语言与运行时分开评价，默认深入到 LANG-L3。
- **Go、Java、Python 中选一门迁移语言**：至少 L2；若它是后端岗位主修，则深入到 L3，Node 保持至少 L2。不强制再增加第三门语言。
- **C++、C#/.NET**：按高性能系统或企业/游戏方向选择一门达到 L2；不作为所有人的同时必修。
- **Rust、PHP、Kotlin、Swift、Dart、Ruby 等**：保持 L1 或技术卡片，按岗位升级。

## 二、语言优先级与方向

**全部语言的逐项教学、运行时辨析与统一知识树见 [[专项-多语言知识树与课程导航|多语言知识树与课程导航]]。** 本页保留跨语言底层实验和选择规则；C/C++、Go、Java、Python、C#、Rust、PHP、Kotlin、Swift、Dart、Ruby 等单语言细节分别进入对应语言文档，ArkTS 使用鸿蒙专项。

| 语言 | 层级 | 主要价值 | 不应误解为 |
| --- | --- | --- | --- |
| C | P0 | 内存、数据布局、编译链接、系统调用与底层实验 | 必须用于所有业务开发 |
| TypeScript/JS | P0 | Web 全栈、异步、浏览器、Node 和工具链 | 只会框架和类型标注 |
| SQL | P0 | 数据建模、查询、事务、索引和执行计划 | ORM 的替代品 |
| Go | P1 推荐后端 | 云原生、高并发、基础设施和简洁部署 | 会 goroutine 就懂并发 |
| Java | P1 企业后端 | JVM、复杂业务、Spring 与国内企业生态 | 只背 Spring 面试题 |
| Python | P1 数据/AI/自动化 | 数据处理、AI 应用、脚本和快速服务 | 性能与并发边界不存在 |
| C++ | P2 高性能方向 | 游戏、量化、音视频、数据库、系统软件 | 互联网业务后端的默认首选 |
| C#/.NET | P2 企业/游戏方向 | 企业应用、Unity、桌面和跨平台服务 | 只用于 Windows 桌面 |
| Rust | P2/P3 | 系统安全、高性能工具、WASM/Tauri | 新手必须马上精通 |
| PHP/Kotlin/Swift/Dart 等 | P1 按岗位/P3 | 存量 Web、JVM/Android、Apple、Flutter | 所有人同时学习 |

## 三、C 与计算机系统底座

### 学习清单

- [ ] 指针、数组、字符串、结构体、对齐、栈/堆和对象生命周期。
- [ ] 编译、汇编、链接、头文件、符号、静态/动态库的基本过程。
- [ ] malloc/free、越界、悬空指针、泄漏和未初始化读取。
- [ ] 文件描述符、系统调用、用户态/内核态和基本错误处理。
- [ ] 使用编译器警告、调试器、AddressSanitizer/等价工具发现问题。

### 必做实验

1. 手写动态数组、链表和哈希表，覆盖扩容、空输入和重复键。
2. 实现简易内存池，记录分配/释放、碎片和越界检测结果。
3. 观察结构体对齐、栈/堆地址和值/引用语义，保存调试证据。
4. 实现文件 Append-only KV 原型，包含启动重放和基本崩溃恢复。
5. 实现最小 TCP/HTTP 服务或代理，处理超时、关闭和错误返回。

层次安排：G1 必做动态数组或哈希表与内存错误诊断；G5 前完成文件/资源与网络实验。内存池、文件 KV 原型按系统岗位选修，不要求初学者在旧 C05 一次完成。已选择的实验均须有测试与资源检查；不能把“没有报错”当作无泄漏、无越界证明。

## 四、操作系统与并发实验

- [ ] 进程、线程、协程、地址空间、虚拟内存、页表和上下文切换。
- [ ] fork/exec、信号、文件描述符、管道和基本 IPC。
- [ ] 互斥锁、读写锁、条件变量、原子操作、死锁和活锁。
- [ ] 阻塞/非阻塞 I/O、select/poll/epoll、事件驱动和背压。
- [ ] CPU 缓存、伪共享、内存可见性和指令重排的认知边界。

实验组合：

1. 有界生产者消费者队列：测试阻塞、唤醒、关闭和竞态。
2. 死锁复现与修复：保留线程转储/调试输出和固定加锁顺序。
3. 比较阻塞 I/O 与事件驱动服务：连接数、吞吐、延迟和资源使用必须同口径。
4. 注入文件描述符泄漏或内存增长，用系统工具定位而非只重启。

## 五、网络与存储深度

### 网络

- TCP 握手/挥手、重传、流量/拥塞控制、Keep-Alive 和 TIME_WAIT。
- DNS、TLS、HTTP/1.1/2/3、连接池、代理和负载均衡。
- 超时、取消、重试预算、网络分区和部分失败。

至少完成一次抓包、一个带超时/取消的客户端和一个有背压意识的代理实验。

### 数据库与存储

- B+Tree、覆盖索引、回表、WAL、redo/undo、MVCC 和检查点。
- 隔离级别、锁、死锁、慢查询、复制延迟、备份恢复和分片。
- Redis 数据结构、过期、持久化、热 key、穿透/击穿/雪崩和一致性。

至少完成：同一查询的执行计划优化、一个事务异常实验、一个崩溃恢复实验和一个缓存故障降级实验。

## 六、第一生产后端语言（按方向选一门深入）

### Go：云原生与高并发

- [ ] interface、error、slice/map、escape analysis 和 GC 基础。
- [ ] goroutine/channel/context、GMP、同步原语和竞态检测。
- [ ] HTTP、数据库、连接池、超时、取消和优雅退出。
- [ ] pprof、benchmark、trace、负载测试和内存/协程泄漏诊断。

**深度实验：** 并发限流器或任务调度器，支持优先级、取消、超时、指标和竞态测试；再用 Go 重写项目 03 一个高热接口，与 Node 同数据同压测比较。

### Java：JVM 与企业业务

- [ ] 集合实现、泛型擦除、异常、资源管理和字节码基础。
- [ ] JMM、锁、线程池、并发集合、虚拟线程按所用版本学习。
- [ ] JVM 内存、类加载、GC、JIT、JFR 和常见 OOM。
- [ ] Spring 生命周期、事务、自调用、依赖边界和真实诊断。

**深度实验：** 手写有界线程池或缓存，验证拒绝、关闭和竞态；使用 JFR/GC/线程转储定位一次性能问题，并保留优化前后数据。

### Python：数据、自动化与 AI 应用

- [ ] 可变性、迭代器/生成器、装饰器、描述符和对象模型。
- [ ] GIL、多线程/多进程/asyncio 的适用边界和取消语义。
- [ ] 类型提示、包管理、pytest、性能剖析和原生扩展边界。
- [ ] FastAPI/Pydantic/SQLAlchemy、后台任务和部署。

**深度实验：** 对同一 I/O 与 CPU 任务分别比较多线程、多进程和 asyncio；完成带类型、测试、权限和诊断的 API 或数据处理服务。

## 八、统一跨语言对照实验

同一业务规则至少在两种语言实现，比较而非只翻译：

| 维度 | 必答问题 |
| --- | --- |
| 类型与边界 | 编译期类型在哪里失效，运行时如何验证不可信输入 |
| 并发 | 线程、协程、事件循环分别如何处理 I/O 与 CPU 任务 |
| 资源 | 内存、连接、文件、锁和取消由谁释放 |
| 错误 | 异常、error、Result 或全局错误如何避免被吞掉 |
| 性能 | 同硬件、同数据、同请求下的吞吐、P50/P95/P99 和资源使用 |
| 诊断 | 各语言用什么 Profiler、转储、日志和测试定位问题 |
| 生态 | 依赖、测试、构建、部署和团队维护成本如何变化 |

## 九、完成标准与常见误区

- [ ] 至少一门语言达到 L3，另一门能独立完成 L2 生产模块。
- [ ] C 底座实验能证明内存、并发或 I/O 中至少两类真实问题。
- [ ] 跨语言报告有相同业务、相同数据和同口径测量，不比较无关 Demo。
- [ ] C++/C# 只按选定方向深入，其他语言仍保留清晰层级。

常见误区：

- 把每门语言的“语法速成”当成多语言能力。
- 同时深入 Go/Java/Python/C++/C#，导致没有任何运行时诊断证据。
- 只看平均耗时，不记录数据量、P95/P99、资源和测试环境。
- 为证明语言优劣选择不同业务、不同数据或不同实现质量的对照。

## 版本与模型边界

GIL 必须注明 Python 解释器、版本与构建模式，不能把 CPython 默认构建的行为推及全部实现或 free-threaded 构建。JMM 与 JVM 内存区域不是同一个概念；GC、JIT、线程与对象布局应按所用版本核对。跨栈对比看同契约、同业务结果与同环境测量，不预设某门语言必然更快。

核心必做实验与阶段映射以 [[专项-核心原理与深度实验|E01/E06/E07/E08]] 为准；操作系统深入实验可在系统/平台专项追加，不把所有可选实验叠加为通用入门门槛。
