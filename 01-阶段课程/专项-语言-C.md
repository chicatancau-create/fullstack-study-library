## 1. 执行模型与边界

- C 源码经预处理、编译、汇编、链接形成目标文件和可执行程序；声明与定义、翻译单元、符号可见性必须分清。
- C 贴近机器模型，不提供自动内存管理、异常、模块对象或内置并发抽象。简单语法不等于简单正确性。
- 区分**实现定义、未指定和未定义行为**。 signed overflow、越界、悬空指针、重复 free、数据竞争等不能靠“本机正常”证明合法。
- ABI、调用约定、字节序、对齐和平台库差异影响互操作；写可移植代码时记录编译器、标准版本和目标平台。

## 2. 值、类型与求值

- 整数宽度/符号、整型提升、usual arithmetic conversions、溢出与隐式转换。
- 浮点精度、NaN/Inf、比较和序列化；货币与精确计数不直接用二进制浮点。
- 数组与指针的关系、数组退化、指针运算边界、`const` 与只读约束。
- 结构体、联合体、枚举、对齐与 padding；不能把内存字节直接当跨平台协议。
- 字符串是 NUL 结尾字节序列，不是安全文本对象；显式处理长度、编码、终止符和缓冲区容量。
- 对象生命周期、存储期、作用域和链接属性；`static` 在不同位置含义不同。
- 未初始化读取、严格别名、有效类型和 `volatile` 的真实用途。

**反例实验：** 构造整数溢出、数组越界、未初始化变量、结构体 padding 和指针生命周期错误，用警告/调试器/Sanitizer 观察，而非只打印答案。

## 3. 函数、控制流与数据结构

- 值传递语义；通过指针共享对象时明确可写性、长度和所有权。
- 函数指针用于回调和表驱动，签名不匹配不能强制转换后调用。
- 手写动态数组、链表、栈、队列和哈希表，定义扩容、缩容、空输入和重复键规则。
- 排序、二分与哈希操作写复杂度；指针缓存局部性可测量但不能脱离数据规模下结论。
- 递归终止、栈深度和迭代替代；大型输入不依赖无限递归。

## 4. 错误与资源生命周期

- 返回值、输出参数和 `errno` 的含义与检查时机；不要在检查前调用其他可能改写它的函数。
- 为每个资源建立“创建者、所有者、释放者、失败时清理路径”：内存、FILE、fd、socket、锁和线程。
- 使用统一清理路径或受控 goto cleanup，避免每个 return 复制释放逻辑。
- 分配大小计算检查溢出；`malloc/calloc/realloc/free` 的成功、失败和零长度行为按标准处理。
- 复制结构体不等于深拷贝；含指针字段的所有权必须文档化。

## 5. 预处理、模块与构建

- 头文件只暴露必要声明，使用 include guard/`#pragma once` 按项目约定；避免宏隐藏控制流和类型错误。
- 条件编译、宏展开副作用、静态/动态库、符号冲突和链接顺序。
- 使用严格警告并将部分警告视为错误；理解警告不是完整静态证明。
- Makefile/CMake 二选一完成可复现构建；记录 debug/release、Sanitizer 与优化参数。

## 6. 并发与系统 I/O

- 进程/线程、地址空间、文件描述符和系统调用；线程共享内存，进程默认隔离。
- C11 threads 或 pthread 按平台选择：mutex、condition variable、atomic 和线程取消/汇合。
- 数据竞争是未定义行为；锁顺序、条件等待谓词、虚假唤醒和关闭协议必须测试。
- 阻塞/非阻塞 fd、select/poll/epoll 按平台学习，处理短读短写、EINTR、EOF 和背压。
- 文件、目录、权限、原子重命名和崩溃恢复；不把 stdio 成功返回当持久化完成。

## 7. 测试、诊断与安全

- 单元测试验证正常、边界和失败；系统调用用受控替身或真实隔离环境分别验证。
- 使用调试器、AddressSanitizer、UndefinedBehaviorSanitizer、LeakSanitizer/Valgrind（按平台）定位问题。
- 检查整数、长度、格式字符串、路径、命令和环境输入；`strcpy/strcat/sprintf/gets` 等危险用法不作为项目默认。
- 安全字符串处理仍需长度与编码检查，不能仅替换函数名就宣称安全。
- 最小权限、资源上限、临时文件、符号链接和错误信息泄露按应用边界验证。

## 8. 教学项目与验收

### 最小项目

动态数组 + 文件 KV：

1. 动态数组支持增删查、扩容和销毁。
2. KV 使用 append-only 文件，启动重放，处理损坏记录。
3. 所有公开函数定义所有权和错误码。
4. 用测试覆盖空文件、截断、重复键、大值和分配失败的可控路径。
5. 用 Sanitizer/等价工具完成内存检查。

### 深度实验

- 实现内存池或有界生产者消费者队列，记录分配、碎片、阻塞、唤醒和关闭。
- 实现最小 TCP/HTTP 服务，处理短读短写、超时、关闭和错误返回。

### 通过标准

- [ ] 能解释指针、数组、生命周期和一次未定义行为。
- [ ] 能说明编译链接、符号和一次 ABI/平台差异。
- [ ] 每个资源都有明确释放路径，错误路径也执行。
- [ ] 至少一个内存错误和一次并发/IO 失败有证据、修复和回归。
- [ ] 能从干净目录构建并运行测试，警告和未定义行为未被隐藏。

## 9. 常见误区

- 把指针当数组长度，把结构体内存布局当网络协议。
- 忽略返回值、短读短写和释放失败路径。
- 以优化级别变化后的“正常输出”判断未定义行为是否存在。
- 为多线程简单加锁，却不证明数据竞争、死锁和关闭顺序。
- 用全局可变状态隐藏所有权，导致测试和复用不可控。
