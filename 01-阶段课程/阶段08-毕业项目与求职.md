# 阶段 08：毕业项目与求职

> 排期口径：本页原第 1–52 周属于 C 压缩主题索引；深度路线实际日期与关口以 [[../03-执行计划/深度路线与工时预算|D01–D96 / G0–G9]] 为准。核心实验可复用项目证据，算法与实验工时已计入总预算。

**建议周次：第 33–36 周｜优先级：P0｜目标：证明独立交付能力，并能清楚解释和捍卫技术决策。**

## 阶段目标

- 完成 [[../02-项目实战/项目04-综合SaaS毕业项目|项目 04：综合 SaaS 毕业项目]]。
- 将四个项目整理为可信作品集，而不是教程截图集合。

## 需求发现与范围工作坊

第 33 周先交付一页需求说明，再写业务代码：

1. **问题证据**：选定一类目标用户，记录其当前流程、痛点、频率和现有替代方案。可访谈真实用户；没有条件时做角色模拟并明确标注，不能把模拟写成真实调研。
2. **用户故事**：最多保留 3 条核心路径，每条写“谁在什么目标下获得什么价值”，避免把页面清单当需求。
3. **验收示例**：核心规则用“给定—当—则”写正常、失败和边界例子，并区分事实、假设与待验证项。
4. **非功能需求**：明确权限、数据保留、可访问性、性能、恢复和成本约束；没有基线的数字标记为目标而非现状。
5. **范围与追踪**：写非目标、MVP、成功指标和“用户故事 → 业务规则 → 测试 → 证据”追踪表。
6. **变更演练**：模拟一次中途新增需求，说明影响、取舍和是否进入后续候选，不直接扩张当前迭代。

## 毕业项目要求

- [ ] 先完成需求发现工作坊，保留调研或角色模拟的边界说明。
- [ ] 独立完成架构、数据模型、API、前端、测试、部署和文档。
- [ ] 至少包含一个复杂业务不变量，并用并发或失败测试验证。
- [ ] 多租户隔离、RBAC、审计日志等高风险能力必须服务端实现。
- [ ] 核心路径可演示，异常路径不形成空白页、重复数据或越权。
- [ ] CI、部署、回滚、备份恢复和核心监控有实际证据。
- [ ] 写明 AI 辅助范围，所有关键代码均可独立解释。

## 作品集整理

每个重点项目准备：

1. 30 秒 elevator pitch：用户、问题、价值和你的职责。
2. 3 分钟演示：一条主流程、一个异常流程、一个技术亮点。
3. 架构图与 ER 图：保持与真实代码一致。
4. 两个关键决策：候选方案、约束、取舍、验证和结果。
5. 一个真实故障：证据、根因、修复、回归测试和预防。
6. 可复现 README、测试报告、部署链接或本地演示方案。

详细要求见 [[../04-资源与评估/面试与作品集|面试与作品集]]。

## 面试准备

### 基础与编码

- [ ] JS 事件循环、闭包、原型、异步取消与错误处理。
- [ ] TS 类型收窄、泛型、运行时边界和 API 建模。
- [ ] React 渲染、状态、Effect、竞态、性能与可访问性。
- [ ] HTTP、缓存、Cookie、CORS、认证授权和常见攻击。
- [ ] SQL、索引、事务、隔离、锁、幂等和 N+1。
- [ ] 常用数据结构、复杂度，以及清晰的编码和测试过程。

### 项目与系统设计

- [ ] 能画架构并解释每个组件为何存在、失败时怎样降级。
- [ ] 能说明一次性能优化的基线、测量、改动和量化结果。
- [ ] 能说明一次意见冲突，如何用证据而非职位达成一致。
- [ ] 系统设计先澄清需求，再估算、建模、设计 API、识别瓶颈和演进。
- [ ] 不会的问题明确边界，给出验证路径，不编造生产经验。

## 求职执行

- [ ] 一页中文简历，必要时准备英文版；项目写结果与证据，不堆技术名词。
- [ ] 每次投递记录岗位、要求差距、日期、进度和面试问题。
- [ ] 每周少量高质量投递，依据反馈调整，而非机械海投。
- [ ] 用 [[../04-资源与评估/能力自检清单|能力自检清单]] 识别差距，只补高频且关键项。
- [ ] 不伪造工作经历、用户量、性能数字或线上职责。

## 阶段验收

- [ ] 毕业项目从干净环境可运行，核心检查实际通过。
- [ ] 一页需求说明、验收示例和追踪表完整，真实调研、角色模拟与假设没有混写。
- [ ] 在限定时间内完成项目演示，无依赖个人记忆的隐藏操作。
- [ ] 连续两次模拟面试能清楚解释项目、基础与一个系统设计题。
- [ ] 简历、代码、演示和叙述一致，所有数字有来源。
- [ ] 已形成下一阶段深化方向：前端、后端或全栈产品交付，而非继续无目标囤课。

## 主线完成后的路线

1. 这里的“毕业”是项目 04 / G6 阶段毕业，不是整个深度路线毕业；还须完成 G7 主修/迁移、G8 接手与 G9 综合实操。默认进入 [[阶段09-中线技术栈与多语言交付|阶段 09]]，默认用 Java/Spring Boot/MySQL 建立有界迁移版本，Vue 按岗位选择。
2. 随后按照 [[../03-执行计划/长期学习路线|长期学习路线]]，每季度从 [[阶段10-长期扩展与专项深化|阶段 10]] 选择一个专项。
3. 若目标岗位明确要求 Java，可提前学习中线；若明确要求 Python、Go、.NET 或其他技术，可调整专项顺序，但保留需求、SQL、测试、安全和部署验收。
4. 完整技术范围见 [[../04-资源与评估/技术栈全景地图|技术栈全景地图]]，36 周毕业不等于长期学习结束。

## 常见误区

- 把“做完课程”当作“具备能力”，却没有独立需求与排错证据。
- 毕业项目范围无限扩张，最后只有登录页和架构图。
- 为面试背标准答案，却无法把答案映射到自己的代码和真实决策。
