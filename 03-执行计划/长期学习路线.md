# 长期学习路线

> 主线实际排期采用 [[深度路线与工时预算|D01–D96 深度路线]]。原“36 周 + 16 周”保留为主题索引，不能再与“第 13 个月开始专项”混为同一个实际日历。

## 一、长期能力结构

- 一套主力栈深入：TypeScript/React/Node/SQL，既能实现也能诊断。
- 一套有界迁移栈：默认 Java/Spring/MySQL，可按目标岗位换 Go/Python/.NET 等；Node 已计为一门后端语言，不强制第三门。
- 一个岗位专项：有运行作品、机制实验、测量、失败恢复与答辩。
- 持续维护：旧项目升级、真实需求变更、代码审查、协作和公开技术表达。

完整工具候选仍见 [[../04-资源与评估/技术栈全景地图|技术栈全景地图]]，主修深度见 [[../04-资源与评估/岗位能力矩阵与验收标准|岗位能力矩阵]]。不把所有语言和框架轮学一遍作为毕业前提。

## 二、中线 16 周模块

默认位于 D69–D84；以下是模块内第 1–16 周，不是另一套实际日历。可替换技术，但不降低权限、数据、测试、诊断与交付要求。

| 模块周 | 重点 | 证据 |
| --- | --- | --- |
| 1–4 | Java 基础、集合/泛型、并发、构建、JVM | CLI 核心迁移、JUnit、线程/资源实验、一次真实诊断 |
| 5–8 | Spring/API/安全/事务/MySQL | 项目 02 同一有界路径，真实 DB、越权、并发与契约测试 |
| 9–12 | Outbox、真实 MQ、幂等、重试/对账、Profile | 崩溃窗口与恢复、指标/Trace、同业务对照 |
| 13–16 | 一个岗位专项、跨栈报告、G7 | 选定模块深化、部署/诊断、技术答辩 |

Java 后端岗位可用可靠事件/JVM/事务作为唯一专项，按 JD 加 Nacos/Sentinel 等；Vue 只在前端迁移有价值时安排。不能在最后一周一次完成所有企业产品集成。

其他方向：Go 重点 context/背压/race/pprof；Python 重点对象模型/asyncio/部署/诊断，GIL 按解释器和构建配置区分；前端方向重点 SSR/构建/组件系统，缩小第二栈产品范围；C++/.NET 等遵循其运行时与资源模型。都要保留同业务契约的迁移比较。

## 三、完成 G9 后的季度机制

每季度最多一个主专项，固定预算中 70% 深入作品、20% 旧系统维护、10% 技术雷达。按兴趣或岗位选择：

| 方向 | 先修 | 一个季度的合理交付 |
| --- | --- | --- |
| 前端架构 | G3/G6、浏览器/构建实验 | 设计系统或复杂页面、性能/可访问性与版本兼容证据 |
| Java/Go 后端 | G4/G5/G7 | 事务/消息/运行时问题的深度模块，不重复堆多个 MQ |
| 云原生/SRE | 单机交付、Linux/网络、恢复 | 可重复 IaC/K8s 环境、SLI/SLO、告警与隔离故障演练 |
| 数据/搜索 | SQL、事务、数据模型 | 一个真实查询问题的搜索/分析存储对照与同步恢复 |
| AI 应用 | API/权限/数据/测试 | 版本化评估、检索权限、无答案、注入/成本与失败策略 |
| 跨端/实时（含鸿蒙） | 前端、网络与安全；鸿蒙需 ArkTS/Stage | 断线/权限/升级/兼容性有证据的有界应用；鸿蒙另需 Hvigor 签名构建与真机边界，见 [[../01-阶段课程/专项-鸿蒙ArkTS与ArkUI应用开发\|鸿蒙专项]] |
| 系统/高性能 | C/OS/并发、性能测量 | C++/Rust/.NET 等按需选择，资源安全与诊断作品 |

每月维护一次旧项目：跑基线、核对依赖支持状态、选择一项兼容升级、补回归和更新文档。每月至少一次算法限时重测、一次设计复盘；把真实发现的问题留证据，而不是编造缺陷数量。

## 四、技术卡片与退出条件

每项新技术先写：服务哪个问题/岗位、适用和不适用场景、最小实验、版本/资料日期、与当前方案差异、测试/诊断/维护成本、升级或停止条件。没有证明新增技术的收益，就继续使用简单方案。

季度复盘只回答：交付了什么、实际验证什么、哪些假设被否定、旧系统是否仍可运行、下季度最值得补哪一个差距。重复收藏却没有编码时，停止新增资料。

## 五、长期发展不由课程授予

独立复杂模块、跨团队协调、容量/成本决策、事故响应和技术领导力，在真实授权工作中积累并由团队验证。可参与开源/同伴项目取得真实协作证据；没有机会时保留模拟标记，不把学习履历包装成工作经验。

持续关注目标岗位官方 JD 的变化，每季度更新一次 [[../04-资源与评估/岗位能力矩阵与验收标准|差距矩阵]]，避免多年围绕已经无关的技术扩展。
