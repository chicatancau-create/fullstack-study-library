# 深度路线与工时预算

> 本文件是深度学习的排期来源。D 表示实际学习周，G 表示能力关口；旧计划 C01–C52 只定位主题。所有工时是初始估算，不能用时间流逝代替通过。

## 一、预算与换算

推荐初始基准为 96 个学习周、每周 25 小时，共 2,400 小时；约 15%（360 小时）在各阶段内预留给重做、环境故障、遗忘复习和补考，正常学习约 2,040 小时。缓冲已含在总量内，不在表外重复添加。

| 每周可持续投入 | 2,400 小时基准所需周数（向上取整） | 2,000–2,800 小时估算范围 |
| --- | ---: | --- |
| 10 小时 | 240 周 | 200–280 周 |
| 15 小时 | 160 周 | 134–187 周 |
| 20 小时 | 120 周 | 100–140 周 |
| 25 小时 | 96 周 | 80–112 周 |
| 35 小时 | 69 周 | 58–80 周 |

换算只说明容量；有基础可通过诊断减项，零基础可能超过区间。工作、考试、假期和停学另外记入日历。连续高强度不能保证同等学习效率，不建议靠熬夜追数。

每四周记录计划/实际工时、已验收交付、返工来源，重估剩余工作量：剩余日历周 = 向上取整（剩余估算小时 ÷ 实际可持续周投入）。没有足够历史数据时标记“低置信度”，不要把早期速度机械外推。

## 三、每个区间怎么执行

### D01–D20：建立底座

- D01–D02：诊断、Git/终端、断点、问题记录；先做纯手工小任务，再做一次辅助工具任务。
- D03–D06：HTML/CSS、表单、响应式、HTTP、Cookie/CORS；C 只学编译、指针和边界。
- D07–D10：C 动态数组/哈希、编译链接与内存诊断；抓包与缓存实验。复杂系统实验延后。
- D11–D14：JS 作用域/原型/模块，Promise 与事件循环；一门语言做算法，避免多语言重复入门。
- D15–D18：TS 建模、运行时校验、CLI、I/O 分层与单测；实现带并发上限和取消的小工具。
- D19–D20：陌生变体、重做与 G2；不把早期题量当成闯关硬指标。

### D21–D44：从 UI 到真实持久化

- D21–D26：React 状态与渲染、异步竞态、路由、表单；项目 01 从第一条主路径开始部署。
- D27–D30：构建产物、缓存与渲染模式、可访问性/性能；完成 G3。
- D31–D34：Node/Fastify 请求链，最小 PostgreSQL 表、参数化 SQL、迁移、真实数据库测试与错误处理，先打通一条持久化主路径。
- D35–D38：认证、资源/租户授权、API 契约；项目 02 联调；不先用内存假仓库宣称持久化交付。
- D39–D42：事务、隔离、Owner 竞态、索引/执行计划、Redis 失效与故障降级。
- D43–D44：迁移/恢复、并发与契约回归、G4；不变量失败必须修复。

### D45–D68：可靠交付与独立设计

- D45–D48：交易状态机、服务端金额、幂等请求指纹、并发库存与重复回调，补对账任务。
- D49–D52：威胁模型、安全/隐私、属性测试、压测方法、定位瓶颈；先测后优化。
- D53–D56：Linux、容器、CI、TLS、日志指标/Trace、SLO；本地 K8s 基础实验。
- D57–D58：兼容发布、备份恢复、至少两类故障演练、G5。
- D59–D62：SaaS 需求、租户模型、三条以内用户路径，早期部署。
- D63–D66：审计、一个可靠性深度模块、灰度/回滚与一次真实代码变更；只选一个深挖方向。
- D67–D68：文档交接、需求变更、G6；遗留问题排优先级。

### D69–D96：主修深化、接手和独立验收

- D69–D72：默认 Java 的语言/构建/并发与 JVM；已有语言基础可先做诊断。迁移的是项目 02 的有界模块。
- D73–D76：Spring/权限/事务/MySQL/真实数据库测试；不要求同时重写前端。
- D77–D80：Outbox/幂等消费/崩溃恢复、运行时诊断；具体 MQ 只选一种。
- D81–D84：一个岗位专项及 G7。专项按“提前并行”执行：D69–D80 已每周投入专项预算，D81–D84 只做收口与验收；选鸿蒙/uni-app 时让位 Java 企业扩展（微服务治理、分布式事务），保留 Java 迁移的主路径、权限与 SQL 证据。Java 后端岗位可直接用上述模块深入；前端方向可缩小 Java 范围、把主修预算用于 SSR/构建/组件系统；鸿蒙方向使用 [[../01-阶段课程/专项-鸿蒙ArkTS与ArkUI应用开发|ArkTS/ArkUI 专项]]，Vue 跨端方向使用 [[../01-阶段课程/专项-uni-app跨端应用开发|uni-app 专项]]，两者分别按各自生命周期、工具链与真机口径验收，仍保留有界迁移证据。不得并行新增多个专项。
- D85–D92：按项目 05 接手、基线、失败先行修复、需求变更、兼容升级、交接与 G8。
- D93–D96：不同题目两轮综合实操、复盘补考、真实 JD 核对与作品集；尚有阻断项则顺延。

## 四、并行上限与每周工时

| 活动 | 小时 | 计时边界 |
| --- | ---: | --- |
| 原理与官方文档 | 4 | 对应当周问题，不无目标囤课 |
| 项目独立编码 | 9 | 包含正常实现，不包含复制教程 |
| 测试、实验与诊断 | 5 | 原理实验、故障、Profile 和修复回归 |
| 算法 / SQL | 4 | 新题、重做、复杂度与限时训练 |
| 写作、评审与复习 | 3 | 证据、周复盘、技术表达、风险沟通 |
| 合计 | 25 | 同一活动只计一次 |

每周最多一条项目主线 + 一个基础训练主题；系统设计可替代一部分理论/写作时间，不能全部叠加。每四周的最后一周优先关闭未通过项，预算内消化返工。专项要求 6 小时算法时，从项目预算调配并顺延，不虚增总量。

## 五、压缩路线与跳级

[[36周执行计划|36 周文件]] 的周次是 C 索引。对应关系：C01→G0；C02–05→G1；C06–10→G2；C11–15→G3；C16–24→G4；C25–32→G5；C33–36→G6；旧 C37–52→G7。G8/G9 为新增独立训练，不能由“C36 已读完”替代。

压缩轨适合已有基础者；零基础选择它，只能在相应证据通过后宣称阶段完成。算法、系统和深度模块沿 D/G 安排，不要求在 C05/C36 机械完成全部深度目标。

允许跳级的条件：同等级陌生任务、失败/边界验证、原理解释全部通过，并记录题目与证据；看过教程、工作年限或自我感觉不能替代。跳级后安排一次延迟复测。

## 六、设备、成本与暂停

- 开始只需编辑器、浏览器、Git 和当前运行时；Linux 实验可用 WSL2/虚拟机/已有 Linux 设备，受控容器环境按能力选择。
- 数据库、MQ、K8s 可分时启动；内存不足时减并发组件或用较小合成数据，记录资源限制，不造容量结论。
- 默认本地或免费条件完成。任何云资源、域名、付费 API、对外发布和真实用户操作另行确认，不是本路线自动授权。
- 暂停时保留代码提交、环境版本、下一步、未关闭问题与恢复条件；恢复后先跑基线，避免直接追进度。
