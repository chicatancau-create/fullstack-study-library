# ADR 001：库存扣减使用行锁 + 条件更新

## 状态

已采纳（2026-11-07）

## 背景

交易 Demo 必须保证库存不为负，并允许同一 SKU 上并发下单。候选方案：

1. 读库存 → 应用层判断 → 写回（无锁）；
2. 乐观锁：`UPDATE ... WHERE stock >= qty AND version = $v`，失败重试；
3. 悲观锁：`SELECT ... FOR UPDATE` 后在事务内扣减，并在 UPDATE 上加 `stock >= qty` 条件。

## 决策

采用方案 3：创建订单事务内先 `SELECT ... FOR UPDATE` 锁定商品行，再执行
`UPDATE p03.inventory SET stock = stock - $2 WHERE sku = $1`；数据库 `CHECK (stock >= 0)`
作为最后防线。

## 原因

- 方案 1 在 READ COMMITTED 下会写偏或超卖。
- 方案 2 需要重试循环与退避，热点 SKU 下重试风暴反而放大延迟。
- 方案 3 语义直观，锁范围仅一行，事务短；`CHECK` 约束保证即使代码回归也不会负库存。

## 代价

- 热点 SKU 串行化。压测（20 并发 / 240 请求 / 单 SKU 库存 150）P50 32.2ms、P95 96.3ms、P99 634.3ms；
  尾延迟来自单行锁排队，不是错误。真实业务应拆分库存桶或使用队列削峰。
- 长时间持锁会阻塞其他下单，事务内禁止外部调用。

## 回滚

若热点不可接受，可改为库存分桶表（每桶一行）或将扣减改为异步队列；订单接口契约不变。
