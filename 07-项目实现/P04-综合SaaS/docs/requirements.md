# 项目 04 需求说明（一页）

> 调研边界：**没有真实用户访谈**。以下痛点与流程来自角色模拟，仅用于确定 MVP 范围，不能当作市场证据。

## 目标用户与当前流程

小型销售团队（3–5 人）用表格和聊天工具跟进客户：客户信息散落在个人表格，跟进记录在聊天里，
负责人无法确认谁在什么时候改过客户，也无法限制成员数量与套餐席位。

## 痛点（假设，待验证）

1. 客户与跟进记录没有组织边界，成员离职后数据留在个人文件里。
2. 客户被误删后无法追溯是谁操作。
3. 邀请成员没有席位上限，免费套餐可能被无限占用。

## 三条核心用户路径

1. owner 创建组织并邀请成员；成员接受邀请后进入组织。
2. 成员创建客户并写跟进记录；admin 删除客户时留下审计。
3. owner 变更套餐；成员数或待接受邀请超过新席位时被拒绝。

## 验收示例（给定—当—则）

- 给定免费组织已有 owner，当并发发出 4 个邀请，则只有 1 个成功（2 席位 − 1 已用）。
- 给定邀请发给 bob，当 alice 使用该 token，则 403；当 bob 接受，则成为成员且审计记录。
- 给定 bob 已被移除，当 bob 再次使用旧邀请 token，则 409，不得恢复成员身份。
- 给定组织有 4 名成员，当 owner 降到免费（2 席位），则 409；移除 2 人后允许降级。
- 给定组织 A 的客户，当组织 B 的成员读取或删除，则 404。
- 给定审计表写入失败，当 admin 删除客户，则 500 且客户未被软删除。

## 非功能需求

- 所有租户查询必须带组织边界；角色在服务端判定。
- 密码使用 scrypt 加盐；会话令牌只存哈希，12 小时过期。
- 审计与业务变更同事务；审计不记录密码、令牌或完整请求体。
- 无文件上传、无第三方通知、无真实支付。
- 性能目标：本机 20 并发邀请不超卖（目标，非生产承诺）。

## 非目标

- 不做实时协作、邮件发送、移动端、计费扣款、数据导出。
- 不做 PostgreSQL RLS；隔离由应用层与测试保证。
- 不做 Docker/K8s/公网 HTTPS（本机无可用运行时，未验证）。

## 成功指标（目标，未测量）

- 核心路径测试全绿；跨租户与席位并发 0 失败。
- 审计覆盖全部高风险动作；删除客户可追溯。
- 新用户按 README 可从空库完成演示，无需手工改库。

## 需求变更演练（迭代 2 中途）

新增“降级套餐时检查席位”。影响：需要统计成员 + 待接受邀请，并在租户行锁内完成；
代价是降级在成员超限时被拒绝，需要先移除成员。决定纳入本轮，因为它是席位不变量的另一半；
“按比例退款/账单”进入后续候选，不扩张当前迭代。
