# ADR 002：共享 schema + tenant_id，应用层隔离

## 状态

已采纳（2026-11-07）

## 背景

多租户隔离候选：每租户独立数据库；共享 schema + `tenant_id`；PostgreSQL RLS。

## 决策

共享 schema（`p04`），所有租户表带 `tenant_id`；每个请求先查 `memberships` 得到角色，
之后所有查询同时匹配 `tenant_id`；跨租户统一返回 404。未启用 RLS。

## 原因

- 独立数据库迁移与连接管理成本高，MVP 不需要。
- RLS 需要为每个请求设置会话变量，连接池复用下容易漏设；本项目用显式 SQL 更容易审计。
- 404 而非 403，避免泄露其他租户资源是否存在。

## 代价

- 隔离正确性依赖每条 SQL；新增查询必须带 `tenant_id`，代码评审需逐条检查。
- 数据库超级用户或 SQL 注入可绕过应用层边界；因此所有输入使用参数化查询。
- 未来可加 RLS 作为纵深防御，应用层检查仍需保留。

## 回滚

若启用 RLS，为租户表添加策略并在事务开始时 `SET LOCAL app.tenant_id`；
现有查询与 API 契约不变。
