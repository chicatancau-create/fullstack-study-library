# ADR 003：审计与业务写入同事务

## 状态

已采纳（2026-11-07）

## 背景

高风险动作（邀请、撤销、移除成员、变更套餐、删除客户）需要可追溯。候选：应用日志；
异步消息/Outbox；同事务写审计表。

## 决策

在业务事务内插入 `p04.audit_events`，失败则整体回滚。审计只记录动作、目标、角色、
计划等最小字段，不记录密码、令牌或完整请求体。

## 原因

- 应用日志与数据库提交不在同一原子边界，可能出现“业务成功但审计丢失”。
- Outbox 适合跨系统副作用；本项目审计就在同一数据库，直接同事务更简单。
- 已用触发器注入 `audit_events` 写入失败，验证客户软删除被回滚（见测试）。

## 代价

- 审计表写入失败会让业务不可用；这是有意的取舍：高风险动作宁可不做，也不能无记录。
- 审计表持续增长，需要归档/分区；当前只保留最近 100 条查询。
- 审计与业务同库，数据库整体丢失时两者一起丢失，需要备份恢复（已做行数校验）。

## 回滚

若改为 Outbox，业务与 outbox 同事务，异步消费者写审计；读取端需容忍延迟。
