- [ ] 使用 Testcontainers 验证真实 MySQL 与消息边界，覆盖重复消息、生产者失败、消费者失败和恢复。
- [ ] 写一份 ADR 比较本地事务、Outbox、Saga 与 Seata；只有存在明确跨服务一致性需求时才实施 Seata，不把分布式事务当默认答案。

企业微服务模块可顺延 2–4 周。第 52 周主路径尚未通过时先补主路径，不以减少权限、真实消息、失败恢复测试或部署验证换取按时完成。

## 七、跨栈对比报告

必须包含：

| 维度 | 需要比较的内容 |
| --- | --- |
| 类型与模型 | TS 类型/运行时校验与 Java 类型/Validation 的边界 |
| 并发 | Node 事件循环、JVM 线程/并发工具及各自 CPU/I/O 场景 |
| 数据 | Prisma/JPA/MyBatis 的 SQL 控制、N+1、事务和迁移 |
| 数据库 | PostgreSQL/MySQL 的约束、索引、锁和执行计划差异 |
| 前端 | React/Vue 的响应式、状态、Effect/watch 和组件测试差异 |
| 工程 | npm/Maven 或 Gradle、模块、依赖、构建和测试组织 |
| 运行 | 内存、启动、诊断、日志、指标、容器和部署成本 |
| 选择 | 团队、存量、招聘、生态、性能和维护约束下的推荐 |

所有性能结论必须注明环境、数据量和测量方法；没有测量时只做定性说明。

## 最小实践汇总

1. 用 Java 重写学习记录 CLI 核心逻辑，复用主线同一组正常、边界和失败测试。
2. 用 Spring Boot 复现项目 02 的 API 契约，验证非法输入、未认证、越权和统一错误，而不是只让成功请求返回 200。
3. 主用 JPA 或 MyBatis 表达“最后一名 Owner 不可删除”，另一种只做有界对照，比较 SQL、事务边界和并发结果。
4. 复用既有前端与 API 验证用户行为；若选择 Vue 迁移，则完成“任务列表 → 新建/编辑 → 评论”并复用至少一条 E2E。
5. 对同一查询查看 PostgreSQL 与 MySQL 执行计划；完成一次 MySQL 迁移、备份恢复和回滚兼容性演练。
6. 在干净环境部署中线版本，记录一次 JVM 或 MySQL 真实诊断，不把“接口能通”当作完成。
7. 完成可靠事件模块：Outbox、幂等消费、Trace、重复/失败/恢复与对账；配置/限流选适合实现，Nacos/Sentinel/Seata 仅按所选 JD 补产品实验与取舍。

## 常见误区

- 把跨栈学习做成语法抄写，需求、权限和测试却全部降低标准。
- 同时主用 Maven/Gradle、JPA/MyBatis 的每个特性，失去对照重点；比较应围绕同一业务规则。
- 用 H2 的成功测试替代 MySQL 真实事务、锁和方言验证。
- 只比较启动速度或代码行数，没有统一环境、数据量和任务就下性能结论。
- 为覆盖企业名词提前堆 Spring Cloud、消息队列和微服务，导致第二套主路径仍未闭环。

## 深度路线取舍

默认预算为 D69–D84，模块周 1–4 语言/并发/诊断，5–8 业务与数据，9–12 消息可靠性，13–16 一个岗位专项与评审。前端主修可缩小 Java 产品范围，将预算用于浏览器/SSR/构建/组件系统；不得同时从零主修 Vue、多个 ORM、多个消息产品和多套治理系统。

按 [[../04-资源与评估/岗位能力矩阵与验收标准|岗位矩阵]] 和 [[专项-核心原理与深度实验|E06/E10]] 验收。没有选 Java 的路线不要求 JVM/Nacos 专项证据，但仍要求自身运行时诊断与等价可靠性验证。
