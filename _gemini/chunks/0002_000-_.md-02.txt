| 前端 | React、Vite、Router；一种服务端状态方案 | 渲染、状态归属、竞态、可访问性、构建与性能 |
| 后端 | Node.js、Fastify、REST、OpenAPI | 生命周期、事件循环、流与背压、契约、鉴权与资源释放 |
| 数据 | PostgreSQL、Prisma、Redis | 先 SQL/约束后 ORM；事务、锁、索引、失效与恢复 |
| 质量 | Vitest、Testing Library、Playwright、真实数据库测试 | 风险驱动、属性/状态机、并发、故障与安全证据 |
| 交付 | Git、Linux、Docker/Compose、CI、Logs/Metrics/Trace | 可复现、兼容发布、SLO、回滚、恢复与 Runbook |

默认迁移线为 Java / Spring Boot / MySQL，用项目 02 的同一主路径、权限矩阵和复杂规则验证迁移，再做 JVM 诊断。Vue 是按岗位选择的前端迁移练习，避免同时从零展开 Java、Vue、MySQL 和微服务治理。

约束：

- 主力后端 Node.js 深入后，从 Java/Go/Python 中选一门迁移；JS/TS + Node.js 构成一套生产后端技术栈证据，不因此强制第三门语言。
- Nacos、Sentinel、Seata、特定云产品是岗位选项；共通要求是配置治理、限流熔断、消息可靠性与一致性。
- 本地 Kubernetes 基础实验用于理解编排；集群治理进入平台专项。课程选择不等于所有公司都要求同一工具。
- C 训练内存与系统直觉，不要求所有 Web 学习者成为 C 专家；C++、Rust、.NET 等按方向深入。
- 采用学习时官方受支持的稳定版本，固定运行时与依赖锁文件；不在单项目混用包管理器。
- 不因技术热度频繁换主线；明确目标岗位要求其他主栈时，可在不降低共通验收的前提下换栈。

## 7. 每周执行

默认 25 小时：原理/文档 4 小时、项目编码 9 小时、测试/诊断/实验 5 小时、算法/SQL 4 小时、写作/复习/评审 3 小时。算法和系统实验已计入总额，不额外叠加。

- 每 45–90 分钟形成一个最小结果；每周只设 1–2 个主目标。
- 普通知识按 1、7、30 天检索练习；算法错题按专项节奏，同次复习不重复计时。
- 每四周复盘工时、证据和阻断项；连续两周完成度低于 60%，减少并行项或顺延，不删权限、正确性与必要验证。
- 日常可用 AI 辅助但审查 diff；独立考核关闭生成式辅助，允许查限定官方文档并记录。
- 至少一份完整辅助交付工单和一份无生成式辅助的独立交付记录；无可用 AI 时可用同伴审查替代并说明，不要求付费工具。
- 不上传秘密、真实用户数据或无权代码；无法解释的实现不计独立完成。
