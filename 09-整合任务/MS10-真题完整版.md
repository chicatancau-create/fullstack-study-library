## 二、逐题原始牛客面经 URL

### 当前缺口
- 当前每题的"来源 URL"是 CodeTop 分页 API，20 题共享一个 URL
- LeetCode 链接只是题目链接，不是面经证据

### 必做清单

#### 1. 分离字段
- `question_url`：LeetCode 题目链接
- `aggregate_source_url`：CodeTop 聚合 API
- `primary_evidence[]`：原始面经证据数组

#### 2. 每条 primary evidence 至少保存
- 牛客原始讨论 URL
- 面经标题、发布时间、访问时间
- 支持该题的最小引文
- 公司/岗位判断依据
- 页面标题和内容哈希
- 核验人及状态

#### 3. 无原始面经的题
- 标为"第三方聚合，待逐题核源"
- 不能计入严格"已核验真题"

#### 4. 链接校验
- 不仅检查 HTTP 200
- 识别登录页、软 404、错误页、公司/题目不匹配

#### 5. 多对多关系
- 允许多个面经支持一题
- 允许一条面经支持多题
- 需记录对应关系

#### 6. 爬虫与合规
- 优先人工核验和使用公开、允许的 API
- 爬虫前检查服务条款、robots、访问频率、版权
- 不得绕过登录、验证码、反爬或付费墙
- 只保存必要元数据和短引文，不批量转载完整面经
- 限制速率、缓存结果、最小化作者个人信息

### 验收
- [ ] 字段分离完整
- [ ] 每条 primary evidence 完整
- [ ] 无原始面经的题目标记正确
- [ ] 链接校验通过

- [ ] 合规检查通过

## 三、内容模板化与岗位分类

### 当前缺口
- 250/250 题都使用同一段通用作答要求
- 所有题目标为"后端/算法"，没有"前端"或"全栈"标记
- 评分点完全相同

### 必做清单

#### 1. 有效答案必须逐题补齐
每题至少包含：
- 核心思路和适用前提
- 关键不变量或正确性论证
- 时间/空间复杂度
- 参考实现或伪代码
- 具有区分度的边界用例及预期输出
- 常见错误、后续追问
- 题目专属评分点

例如"无重复字符的最长子串"应评价：
- 滑动窗口
- 最近位置
- 左边界更新
- 重复字符场景

而不是泛泛评价"空输入、重复值、表达"。

#### 2. 自动质量门禁
- 禁止统一模板段落
- 禁止题文不符的通用评分点
- 校验代码可执行及测试通过
- 校验复杂度与实现一致
- 人工抽查高风险题和全部新增题

#### 3. 前端/全栈补充
不能仅把现有算法题改标签。应针对 MS5 原岗位方向采集新题：
- 淘系前端、到家前端、微信小程序
- 微信支付全栈、蚂蚁全栈、AI 全栈、网约车全栈
- React、浏览器、CSS、JS/TS、SSR、缓存、可访问性、构建优化、Web 性能
- Node API、SQL、缓存、跨端契约、部署与故障诊断

#### 4. 公司×岗位×题型矩阵
建立矩阵，并设明确最低覆盖目标。
原始面经未写岗位时应标"岗位未标注"，不能统一推断为后端。

- [ ] 前端/全栈题补充完整
