# MS4 · 自建可判定题库

> 目标：把当前 catalog 中"索引多、可做题少"的题库，转化为**有标准答案、有自动判定、有评分**的自建题集。
> 工作量：中。优先级：P1。
> 前置：MS1、MS2 完成（部分题目依赖项目与实验）。

## 全局规则

1. 在 `08-判定题库/` 下新增 `专题题库/` 子目录。
2. 每个专题题库必须有：
   - `题面/`：每题一个 .md，含题目、输入、输出、约束
   - `答案/`：标准答案（学生不可见）
   - `判定脚本/`：自动判定（跑测试或对比输出）
   - `数据/`：schema、seed、上下文等
   - `README.md`：题库说明、覆盖能力点、评分方式
3. 提交格式：`feat(sql): MS4-SQL 50 题`、`feat(rag): MS4-RAG golden set`。

## 专题 1：SQL 离线可判定题集（50 题）

### 范围
- 基础查询（10 题）：SELECT / JOIN / GROUP BY / HAVING / 子查询
- 窗口函数（8 题）：ROW_NUMBER / RANK / LAG/LEAD / 累计求和
- 事务与锁（8 题）：隔离级别、写偏差、死锁、SELECT FOR UPDATE
- 执行计划（8 题）：索引选择、Seq Scan vs Index Scan、JOIN 策略
- 迁移与恢复（8 题）：在线加字段、改类型、回滚、备份恢复
- 方言差异（8 题）：PostgreSQL vs MySQL 行为差异

### 交付物
- `数据/schema.sql`：建表语句
- `数据/seed.sql`：测试数据
- `题面/Q01.md` ~ `Q50.md`
- `答案/Q01.sql` ~ `Q50.sql`
- `判定脚本/judge.sh`：跑学生 SQL、对比预期结果、输出通过/失败
- `README.md`：覆盖 M07 能力矩阵的哪些子项

## 专题 2：RAG golden set

### 范围
- 检索质量（30 条）：标准问题 + 标准引用文档 + 可接受答案
- 拒答（10 条）：超出知识库的问题，期望拒答
- 越权（10 条）：跨租户问题，期望拒绝
- 提示注入（10 条）：含注入攻击的上下文，期望不被劫持
- 成本基线（5 条）：固定问题，记录 token 用量与延迟

### 交付物
- `数据/corpus/`：知识库文档（版本化）
- `数据/golden.jsonl`：65 条 golden 样本
  ```json
  {"id": "Q001", "type": "retrieval", "question": "...", "expected_docs": ["doc1", "doc3"], "acceptable_answer": "...", "cost_baseline": {"tokens": 150, "p95_ms": 800}}
  ```
- `评测脚本/eval.py`：跑 RAG 系统、计算指标
- `指标/`：Context Precision / Recall / Faithfulness / 引用正确率 / 拒答率 / 越权检索率 / P95 / 成本
- `README.md`：覆盖 M13/M14/M15 能力矩阵

## 专题 3：后端实操题（30 题）

### 范围
- API 契约（8 题）：OpenAPI 兼容、版本演进、废弃字段
- 对象级授权（8 题）：越权、跨租户、字段级权限

- Outbox 与消息（4 题）：崩溃窗口、死信、对账
- JVM 诊断（4 题）：内存泄漏、GC 调优、线程死锁

### 交付物
- 每题一个小项目（含起始代码 + 隐藏测试）
- 判定脚本：`npm run test:hidden` 或 `mvn test`
- 评分指南
