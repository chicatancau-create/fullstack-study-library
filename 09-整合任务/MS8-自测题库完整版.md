# MS8 · 自测题库完整版（G0–G9 全范围）

> 目标：把 G0–G9 从"骨架版"补齐为**完整自测版**，达到 `04-资源与评估/综合实操考核与上岗准入.md` 原始验收标准。
> 定位：**自学自测题库**，学习者自己读题、自己做、自己对答案、自己评分。
> 前置：MS6、MS7 完成。

## 核心理念（重要方向修正）

### 这是自学资料库，不是考试系统

- **学习者自己对自己负责**，不需要防作弊
- **所有答案、解析、评分标准都可以公开**，因为学习者需要自己对照
- **不需要教师端/学生端隔离**，那是考试系统的设计，不适用于自学

### 目录结构（自学版）

把现有 `08-判定题库/` 重命名为 `08-自测题库/`（或保留名字但改内部结构）：

```
08-自测题库/
├── README.md                    # 自学使用指南
├── G0-环境与工程习惯/
│   ├── README.md                # 本关说明、学习目标、自评标准
│   ├── 题目.md                  # 学习者读的题面
│   ├── 起始代码/                # 学习者从这里开始
│   ├── 参考答案/                # 做完后对照（公开）
│   ├── 自测脚本/                # 学习者自己跑
│   ├── 评分指南.md              # 学习者自评 rubric
│   └── 故障变体/                # 多版本练习（公开）
├── G1-...
├── 专题题库/
│   ├── SQL50/
│   ├── RAG-GoldenSet/
│   ├── 后端实操30/
│   └── 全英文面试10套/
└── 国内大厂真题/
```

### 关键改变

1. **不再追求"物理隔离"**：所有答案公开，学习者自己决定何时看
2. **G8 改为"陌生系统接手练习"**：提供固定旧系统 + 缺陷清单（公开）+ 学习指南，学习者自己诊断、自己修复、自己对答案
3. **G9 改为"综合实操自测"**：两套试卷（A/B）公开，学习者自己计时、自己评分、自己复盘
4. **评分指南改为"自评 rubric"**：学习者自己打分，不需要外部评估者

## G8 陌生系统接手与团队交付 · 完整自测版（方向修正）

### 当前缺口
- 只有单函数 `normalizeOrders`
- 无固定旧系统、无植入缺陷、无接收人剧本

### 必做清单（自学版）

#### 1. 固定旧系统
- 基于 P02 改造成"遗留系统"
- 固定 commit
- 合理历史、文档滞后、部署和种子数据
- 打不可变标签 `g8-legacy-v1`

#### 2. 植入缺陷（公开）
- refresh 轮换并发重放
- 默认 JWT secret、内部错误信息泄露
- 任务更新不使用 version，造成丢失更新
- 列表只按 createdAt 排序，分页不稳定
- Task.ownerId 数据归属约束不完整
- 一处跨租户授权回归
- 一处慢查询

#### 3. 学习指南（公开）
- **失败先行基线**：固定环境和种子，基线测试必须有预期通过和预期失败分组
- **需求变更**：任务批量分配/批量状态更新，返回逐项结果
- **兼容升级**：增加任务事件或新字段，采用 expand/contract
- **性能诊断**：固定 10k/100k 种子，缺索引或不稳定排序问题
- **交接练习**：学习者写交接文档，自我评估"可接手/有条件接手/不可接手"

#### 4. 参考答案（公开）
- 完整修复过程 + 解释
- 每个缺陷的根因分析
- 修复后的测试

#### 5. 自评 rubric（公开）
- 缺陷修复率
- 交接文档质量

## G9 综合实操 · 完整自测版（方向修正）

### 当前缺口
- 只有 `solvePaper('A'|'B')` 单函数
- 无独立 A/B 试卷、无 12 小时计时、无 100 分制评分

### 必做清单（自学版）

#### 1. 两套独立试卷（公开）

| 环节 | A 卷：预约/排班 | B 卷：订单履约/对账 |
|---|---|---|
| 业务规则 | 时段冲突、候补、时区、座位容量 | 库存、支付、退款、履约、对账 |
| 权限 | 组织成员/viewer、跨租户预约 | 用户/管理员、订单归属 |
| 并发 | 同时段只成功一个 | 库存和幂等回调 |
| 故障 | 丢失更新、缓存旧读、迁移不兼容 | 重复消息、Outbox 崩溃、慢查询 |
| 算法 | 依赖排程 | 事件对账 |
| SQL | 利用率与重叠时段 | 订单/支付/库存差异 |
| 发布 | 新增 hold 到期字段 | 新增履约状态与兼容迁移 |

要求：
- 不同学生目录、起始代码、种子、故障、答案、隐藏测试和题面哈希
- 只共享通用计时器、基础镜像和评分框架
- 难度通过预试校准

#### 2. 12 小时自测计时（公开）
- 学习者自己计时：60+300+120+90+90+60=720 分钟
- 提供计时脚本：start/status/pause/resume/checkpoint/finalize
- 学习者自己记录每阶段提交、文件哈希、实际用时

#### 3. 100 分制自评 rubric（公开）

| 维度 | 分值细分 |
|---|---|
| 业务正确性 25 | 主路径 8；数据不变量 8；状态/并发/幂等 5；边界与失败语义 4 |
| 安全与隐私 20 | 对象/租户授权 8；认证与可信输入 5；秘密和错误边界 4；数据最小化 3 |
| 测试与诊断 20 | 失败先行 5；单元/集成/E2E 6；真实依赖和并发 5；根因证据 4 |
| 工程与可靠交付 15 | 干净启动 4；可复现/CI 3；迁移兼容 3；发布恢复 3；资源清理 2 |
| 原理、算法与 SQL 10 | 算法正确性/复杂度 4；SQL 3；机制解释与反例 3 |
| 沟通、评审与交接 10 | 澄清 2；设计/取舍 2；评审处置 2；Runbook 2；答辩与自我修正 2 |

通过条件：
- 每轮总分至少 80
- 各维度至少达到 60%
- 两轮都通过

#### 5. 复盘模板（公开）
