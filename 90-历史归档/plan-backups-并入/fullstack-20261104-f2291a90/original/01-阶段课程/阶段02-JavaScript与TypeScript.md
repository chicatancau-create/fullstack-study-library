# 阶段 02：JavaScript 与 TypeScript

**建议周次：第 6–10 周｜优先级：P0｜目标：用类型明确、可测试的代码解决真实问题。**

## 阶段目标

- 理解 JavaScript 的执行模型、作用域、原型、模块和异步机制。
- 使用 TypeScript 表达业务状态与 API 边界，而不是到处使用 `any`。
- 能编写带单元测试的纯函数、异步流程和 Node.js 小工具。

## 学习清单

### JavaScript 核心

- [ ] 原始类型、对象、数组、相等比较、类型转换和可变性。
- [ ] 作用域、闭包、`this`、调用方式、原型与原型链。
- [ ] 解构、展开、可选链、空值合并、集合 Map/Set。
- [ ] 迭代器、常用数组方法，以及排序和修改原数组的副作用。
- [ ] ES Modules、依赖边界、循环依赖和动态导入。
- [ ] Error 类型、异常传播、`try/catch/finally`，不吞异常。

### 异步与浏览器事件

- [ ] 事件循环、调用栈、任务与微任务的基本执行顺序。
- [ ] Promise 状态、链式调用、错误传播、`async/await`。
- [ ] `Promise.all/allSettled/race` 的差异和适用场景。
- [ ] 定时器、AbortController、超时、取消和重复请求。
- [ ] DOM 事件、冒泡、捕获、委托和默认行为。
- [ ] Fetch 的 HTTP 错误与网络错误差异；非 2xx 不必然 reject。

### TypeScript

- [ ] 基础类型、字面量、联合、交叉、接口、类型别名和枚举替代方案。
- [ ] 泛型、约束、类型推导、函数签名和可空值建模。
- [ ] 类型收窄、判别联合、`unknown` 与运行时校验。
- [ ] `Partial/Required/Pick/Omit/Record/ReturnType` 等常用工具类型。
- [ ] 类型只存在于编译期；外部输入不能仅靠类型断言保证安全。
- [ ] `tsconfig` 的模块、严格模式和输出配置；理解编译与运行边界。

### Node.js 与质量基础

- [ ] npm scripts、依赖分类、语义化版本和锁文件。
- [ ] 文件、路径、流、Buffer、环境变量和退出码的基本使用。
- [ ] 使用 Vitest 编写单元测试：正常、失败、边界和异步场景。
- [ ] 测试隔离、固定时间/随机输入、避免依赖执行顺序。

### 算法与正确性训练

按 [[专项-算法与数据结构深度训练|算法与数据结构深度训练]] 同步进行：第 6–10 周重点覆盖数组、哈希、链表、双指针、滑动窗口、栈队列、二叉树和二分。每周至少 4 小时用于新题、错题重做与限时编码，TS 类型系统不能代替算法正确性证明。

## 最小实践

算法部分按专项周计划留下有效题量、限时编码和错题重做记录；不以 CLI 项目替代算法验收。

实现一个“学习记录 CLI”：

- 支持新增、查询、完成、统计和 JSON 文件持久化。
- 使用判别联合表示命令，使用显式错误类型处理非法输入。
- 支持文件不存在、空文件、损坏 JSON、重复 ID、并发风险的识别或处理。
- 对核心逻辑写单元测试；I/O 与业务逻辑分离。
- README 写清安装、命令示例、退出码和已知限制。

## 阶段验收

- [ ] 能预测并解释典型事件循环代码的输出顺序。
- [ ] 能独立实现带超时、取消和错误处理的异步请求封装。
- [ ] 核心公共接口无 `any`，外部数据进入系统前有运行时校验。
- [ ] 单元测试实际执行通过，并能证明测试会在业务逻辑破坏时失败。
- [ ] 能解释值传递/引用、浅拷贝/深拷贝和不可变更新的影响。
- [ ] 达到本阶段算法里程碑，能限时完成基础专题并分析复杂度与变体。

## 常见误区

- 只背语法，不写完整程序；只测试 happy path。
- 用类型断言消除编译错误，导致类型与运行时数据不一致。
- 在异步循环中误用 `forEach`，或把串行 await 当作默认最佳方案。
