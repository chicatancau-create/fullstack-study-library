# 阶段 05：数据库与缓存

**建议周次：第 21–24 周｜优先级：P0｜目标：保证数据正确，再讨论查询速度和缓存。**

## 阶段目标

- 能从业务约束设计关系模型，并手写、分析和优化 SQL。
- 理解事务、隔离、锁、幂等和迁移风险。
- 完成项目 02 的数据层，明确缓存不能替代事实数据源。

## 学习清单

### PostgreSQL 与数据建模

- [ ] 表、行、主键、外键、唯一、非空、默认值和检查约束。
- [ ] 一对一、一对多、多对多；关联表与反向查询。
- [ ] 规范化与适度反规范化；不用 JSON 字段逃避所有建模。
- [ ] 时间统一存储策略、时区转换、金额精度和软删除取舍。
- [ ] 标识符、枚举、文本、JSONB 等类型的合理使用。
- [ ] 数据约束尽量靠近数据库，应用校验不能替代唯一约束。

### SQL 与查询分析

- [ ] `SELECT/WHERE/JOIN/GROUP BY/HAVING/ORDER BY/LIMIT`。
- [ ] 内连接、左连接及其对 NULL 的影响；分页和稳定排序。
- [ ] 子查询、CTE、窗口函数的基本使用。
- [ ] 参数化查询，绝不拼接不可信 SQL。
- [ ] 索引结构直觉、复合索引顺序、选择性、覆盖与写放大成本。
- [ ] `EXPLAIN (ANALYZE, BUFFERS)` 的基础阅读；用真实数据验证。
- [ ] N+1 查询的识别和修复；批量查询不等于无限制 IN。

### 事务、并发与迁移

- [ ] ACID、事务边界和连接管理。
- [ ] 脏读、不可重复读、幻读，以及常见隔离级别的作用。
- [ ] 行锁、唯一约束冲突、死锁、重试与锁顺序。
- [ ] 乐观锁/版本号、悲观锁的适用场景。
- [ ] 幂等键、去重约束、状态机和“先查再插”竞态。
- [ ] 迁移的前向/回滚策略；扩展—迁移—收缩优于直接破坏性修改。
- [ ] 备份、恢复演练、保留策略；只有备份未恢复验证不算可靠。

### Prisma 与 Redis

- [ ] Prisma schema、client、迁移、事务和原始 SQL 的边界。
- [ ] 理解 ORM 生成的 SQL；不要用 ORM 隐藏事务和查询成本。
- [ ] Redis 字符串、哈希、列表、集合、过期和基本原子操作。
- [ ] Cache Aside、TTL、缓存穿透/击穿/雪崩的概念与基本防护。
- [ ] 缓存失效、数据一致性、热点 key 和内存上限。
- [ ] 分布式锁并非默认答案；优先数据库约束、原子操作和幂等设计。

## 最小实践

围绕项目 02 完成：

1. 用户、工作区、成员、项目、任务、评论的 ER 图和约束。
2. 手写 10 个核心 SQL：多表查询、聚合、窗口函数、稳定分页。
3. 用数据证明一个慢查询的索引优化前后差异，同时记录写入成本。
4. 编写并发创建同名资源的实验，证明唯一约束能阻止重复。
5. 为一个多步业务操作确定事务边界，并测试中途失败后的状态。
6. 给只读列表增加可删除的缓存层，比较命中、失效和源库失败行为。

## 阶段验收

- [ ] ER 图、表结构、业务不变量一致，关键约束有数据库测试。
- [ ] 能解释至少一个查询计划，而非只凭经验添加索引。
- [ ] 并发与事务失败测试通过，不产生重复数据或半完成业务状态。
- [ ] 迁移可在测试环境重复验证，备份恢复流程有实际演练记录。
- [ ] 缓存关闭后核心功能仍正确，只是性能或可用性按设计降级。
- [ ] 能说明为何当前使用模块化单体和 PostgreSQL，而非提前拆分微服务。

## 常见误区

- 把事务当万能锁；长事务包含外部 HTTP 请求，扩大锁竞争。
- 只在应用层检查唯一性，在并发下产生重复数据。
- 加缓存后没有失效策略、故障策略和一致性说明。
