# 面试与作品集

## 一、作品集的最小组合

不必把全部练习放入简历。推荐：

1. **综合 SaaS**：证明独立需求、权限、复杂业务与完整交付。
2. **电商交易 Demo 或协作平台**：证明事务、并发、测试与后端深度。
3. **个人博客**：作为前端与内容展示补充，有亮点再放。

每个项目必须能回答：

- 为谁解决什么问题？为什么这样限定范围？
- 你独立完成了什么？哪些由教程、团队或 AI 辅助？
- 架构为什么这样设计？候选方案和代价是什么？
- 如何保证权限、数据一致性、异常与重复请求正确？
- 实际运行了哪些测试、构建、部署、恢复和性能验证？
- 当前还有什么未完成或不适用的场景？

## 二、README 推荐结构

```text
项目名与一句话价值
演示 / 截图 / 视频
核心功能与明确非目标
技术栈与架构图
本地安装、配置、启动、测试、构建命令
数据库迁移与种子数据
核心业务流程与权限模型
关键设计决策和取舍
测试与性能证据
已知限制、风险、后续计划
```

注意：`.env.example` 只提供安全示例，不放真实 Token、密码或连接串。

## 三、项目描述公式

使用“**问题 + 行动 + 验证 + 结果/限制**”，不要只列技术栈。

较弱写法：

> 使用 React、Node.js、PostgreSQL 和 Redis 开发 SaaS 平台。

更有证据的写法：

> 独立设计并实现多组织任务协作应用，通过服务端资源鉴权、数据库唯一约束和事务保护租户隔离及并发写入；编写权限与并发集成测试，并在 README 记录部署、恢复演练和当前容量限制。

数字只有在真实测量并能解释环境时才写，例如“在何种数据量、并发和实例配置下，P95 从多少变为多少”。

## 四、面试准备矩阵

| 主题 | 必须能解释 | 与自己的项目连接 |
| --- | --- | --- |
| JS/TS | 事件循环、异步取消、类型收窄、运行时校验 | 请求封装、DTO 与业务状态模型 |
| React | 渲染、状态、Effect、竞态、可访问性 | 一个真实 Bug 和一次测量后优化 |
| HTTP/Web | 缓存、Cookie、CORS、认证与安全 | 登录设计、跨域或缓存故障 |
| Node/API | 分层、校验、错误、授权、超时与资源释放 | OpenAPI、统一错误和优雅退出 |
| SQL/数据 | Join、索引、事务、隔离、锁、幂等 | 并发实验、执行计划和迁移 |
| 测试 | 测试层级、隔离、异常与并发 | 一条失败先行的回归测试 |
| DevOps | 容器、CI/CD、HTTPS、日志指标、回滚 | 一次部署故障或恢复演练 |
| 系统设计 | 澄清、估算、建模、瓶颈、演进 | 项目当前架构与下一量级演进 |

## 五、系统设计回答顺序

1. **澄清**：用户、核心功能、非目标、规模、延迟、一致性、可用性和成本。
2. **估算**：QPS、数据量、存储增长、带宽与读写比；说明假设。
3. **契约**：核心 API、数据模型、权限和状态机。
4. **高层设计**：客户端、应用、数据库、缓存/异步组件及数据流。
5. **深挖**：选择一个瓶颈或正确性问题，讨论索引、事务、幂等、缓存或队列。
6. **可靠性**：超时、重试、降级、备份、监控、安全和故障恢复。
7. **演进**：从简单单体到扩展方案的触发条件，不直接堆分布式组件。

## 六、行为面试

准备 5 个真实故事：

- 最困难的技术问题；
- 一次错误决策及修正；
- 一次需求变化或范围收敛；
- 一次通过证据解决分歧；
- 一次主动补测试、改善可靠性或学习新技能。

使用“情境—任务—行动—结果—反思”，不虚构团队、生产职责和用户数据。

## 七、模拟面试验收

- [ ] 45 分钟内完成一道中等编码题，先澄清并测试边界。
- [ ] 20 分钟讲解项目，不被架构图之外的问题轻易打断。
- [ ] 45 分钟完成一个常见系统设计，有估算与取舍。
- [ ] 遇到未知问题时能提出验证路径，而非连续猜测。
- [ ] 录音复盘术语、语速、逻辑和未答出的基础问题。

## 八、投递与复盘

记录岗位 JD、核心要求、差距、投递日期、轮次、问题和反馈。每 5–10 次高质量投递复盘一次：

- 无简历反馈：检查岗位匹配、项目表达与简历证据。
- 有技术面但无后续：按问题矩阵补基础与项目深挖。
- 只有特定领域薄弱：针对岗位做最小补学，不重开整套课程。
