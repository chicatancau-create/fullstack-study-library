# 阶段 09：中线技术栈与多语言交付

**建议时间：第 37–52 周｜优先级：P1｜前置：阶段 08 或主线项目 04 达到可交付状态。**

## 阶段目标

- 使用 **Java/Spring Boot + Vue 3 + MySQL** 完成第二套企业全栈交付。
- 将主线的 HTTP、权限、SQL、事务、测试和部署知识迁移到不同语言与生态。
- 能比较 Node/React/PostgreSQL 与 Java/Vue/MySQL，而不是只罗列语法差异。

## 一、Java 与 JVM 基础

- [ ] 基本类型、对象、字符串、泛型、集合、Optional、异常和资源管理。
- [ ] 面向对象、接口、组合、不可变对象、record/sealed type 等按所用版本学习。
- [ ] Stream、Lambda、函数式接口及其调试和性能边界。
- [ ] 线程、线程池、锁、并发集合、CompletableFuture、虚拟线程（按版本选学）。
- [ ] JVM 内存模型直觉、类加载、GC、JIT、Stack/Heap 与常见 OOM。
- [ ] JFR、JMC、jstack/jmap 或等效工具的基础诊断。
- [ ] Maven 或 Gradle 主用一个，另一个能读；依赖作用域、版本冲突和可复现构建。

**练习：** 将阶段 02 的学习记录 CLI 核心逻辑改写为 Java，使用 JUnit 5 覆盖同一组边界测试。

## 二、Spring Boot 企业后端

- [ ] Spring IoC/DI、Bean 生命周期、配置、Profile 和模块边界。
- [ ] Spring MVC、Controller/Service/Repository、DTO 与领域模型边界。
- [ ] Bean Validation、统一错误、过滤器/拦截器、序列化和 OpenAPI。
- [ ] Spring Security 过滤器链、认证、Session/JWT、CSRF、方法与资源授权。
- [ ] Actuator、健康检查、指标、结构化日志和敏感端点保护。
- [ ] Spring Boot Test、JUnit 5、AssertJ、Mockito、MockMvc/RestAssured。
- [ ] Testcontainers 真实数据库集成测试，不用 H2 代替所有生产行为验证。
- [ ] Lombok、MapStruct 等代码生成工具按项目选择，理解生成代码与调试成本。

## 三、MySQL 与 Java 数据访问

- [ ] MySQL 数据类型、字符集、时区、InnoDB、索引与执行计划。
- [ ] MySQL 与 PostgreSQL 在 SQL 方言、NULL、唯一约束、锁和隔离上的实际差异。
- [ ] JPA/Hibernate 实体、关联、持久化上下文、脏检查、懒加载与 N+1。
- [ ] MyBatis Mapper、动态 SQL、显式 SQL 控制和复杂查询。
- [ ] Spring Transaction 传播、回滚规则、自调用陷阱与事务边界。
- [ ] Flyway 或 Liquibase 迁移，备份恢复与兼容发布。
- [ ] 连接池、慢查询、锁等待、死锁和批量处理。

**练习：** 同一“最后一名 Owner 不可删除”规则分别用 JPA 和 MyBatis 表达，比较事务、SQL 和测试。

## 四、Vue 3 前端工程

- [ ] Composition API、ref/reactive、computed、watch/watchEffect 的边界。
- [ ] SFC、props/emits、slots、provide/inject、Composable 和组件设计。
- [ ] Vue Router、Pinia、服务端状态与本地状态分离。
- [ ] 表单、异步请求、竞态、取消、错误/空/加载和权限反馈。
- [ ] Vue Test Utils + Vitest、Playwright、MSW。
- [ ] Element Plus、Ant Design Vue、Naive UI 等选一个练习，不替代可访问性。
- [ ] Nuxt 的 SSR/SSG/数据获取作为后续扩展，不与 Vue 基础并行。

**练习：** 用 Vue 重写项目 02 的“任务列表 → 新建/编辑 → 评论”主路径，并复用既有 API 契约。

## 五、中线综合交付

以 [[../02-项目实战/项目02-协作任务平台|项目 02]] 为需求基准，实现一个独立中线版本：

- Java/Spring Boot 后端、Vue 3 前端、MySQL 数据库。
- 一条主路径 + 一个复杂业务不变量 + 一套权限矩阵。
- 单元、真实数据库集成、越权、并发和关键 E2E 测试。
- Docker/Compose、CI、日志、健康检查和部署文档。
- 迁移、备份恢复和至少一次故障诊断。

## 六、跨栈对比报告

必须包含：

| 维度 | 需要比较的内容 |
| --- | --- |
| 类型与模型 | TS 类型/运行时校验与 Java 类型/Validation 的边界 |
| 并发 | Node 事件循环、JVM 线程/并发工具及各自 CPU/I/O 场景 |
| 数据 | Prisma/JPA/MyBatis 的 SQL 控制、N+1、事务和迁移 |
| 数据库 | PostgreSQL/MySQL 的约束、索引、锁和执行计划差异 |
| 前端 | React/Vue 的响应式、状态、Effect/watch 和组件测试差异 |
| 工程 | npm/Maven 或 Gradle、模块、依赖、构建和测试组织 |
| 运行 | 内存、启动、诊断、日志、指标、容器和部署成本 |
| 选择 | 团队、存量、招聘、生态、性能和维护约束下的推荐 |

所有性能结论必须注明环境、数据量和测量方法；没有测量时只做定性说明。

## 阶段验收

- [ ] 中线版本主路径可运行，权限与业务不变量有测试证据。
- [ ] Java、Vue、MySQL 不依赖教程能完成常规调试和修改。
- [ ] 能阅读 JVM 与 MySQL 至少一类真实诊断信息。
- [ ] 跨栈报告引用真实代码、测试和部署结果，不凭印象下结论。
- [ ] 能说明何时继续使用主线、何时采用中线，以及迁移代价。
- [ ] 已进入 [[../03-执行计划/长期学习路线|长期学习路线]] 的专项选择，而非同时开启所有扩展。
