# 阶段 00：开发环境与工程习惯

**建议周次：第 1 周｜优先级：P0｜目标：建立可复现、可验证、可回滚的工作方式。**

## 阶段目标

- 能使用终端、编辑器、浏览器开发者工具和 Git 完成最小开发闭环。
- 能区分源码、依赖、构建产物、环境配置与秘密信息。
- 建立“先复现、再修改、后验证”的习惯，不依赖复制粘贴碰运气。

## 学习清单

### 工具与终端

- [ ] 安装并确认 Git、Node.js Active LTS、npm 和编辑器可用。
- [ ] 掌握路径、当前目录、文件查看、目录切换、环境变量和进程终止。
- [ ] 理解 Shell、终端、编辑器、运行时和包管理器各自的职责。
- [ ] 学会查看版本与帮助信息；不执行来源不明的复制命令。

### Git 与协作基础

- [ ] `init / status / diff / add / commit / log / restore / switch`。
- [ ] 分支、合并、冲突来源和 `.gitignore`。
- [ ] 理解工作区、暂存区、提交历史和远程仓库。
- [ ] 小步提交；提交信息说明“为什么改”，不只写“更新”。
- [ ] 未理解影响前，不在真实项目上使用强制推送、硬重置或批量清理。

### 调试与问题记录

- [ ] 阅读完整错误信息、堆栈、退出码和最小复现步骤。
- [ ] 使用断点、变量检查、网络面板和日志定位问题。
- [ ] 区分症状、触发条件、根因和修复。
- [ ] 每次求助携带环境、预期、实际、复现和已尝试方案。

### AI 辅助与独立验证

AI 是解释、质疑和审查工具，不是验收者。每次用于学习或编码时走同一条闭环：

1. **先自己定义**：写出目标、最小复现、当前假设和不允许改变的约束。
2. **限定任务**：优先让 AI 解释概念、列候选方案、补充边界测试或审查指定 diff，不直接接受整项目生成。
3. **核对来源**：API、版本和安全结论查官方文档；生成代码按不可信输入审查权限、注入、秘密和依赖风险。
4. **实际验证**：小步接入，运行正常、失败和边界测试；AI 声称“已通过”必须附上自己本轮执行的证据。
5. **脱离辅助复现**：关闭对话，独立重写关键部分并解释取舍；不能解释的内容不标记为掌握。

## 最小实践

建立一个 `web-foundations-lab` 练习仓库：

1. 创建 HTML 页面、笔记目录和 `.gitignore`。
2. 完成至少 5 次小而明确的提交。
3. 制造并修复一次合并冲突。
4. 在笔记中记录一个真实 Bug 的复现、假设、证据、根因和验证。
5. 在另一目录模拟干净克隆，确认按说明可以继续开发。
6. 让 AI 审查一次明确范围的 diff，逐条记录接受或拒绝的理由，并用测试验证最终改动。

## 阶段验收

- [ ] 不看教程完成仓库创建、分支修改、合并和提交历史检查。
- [ ] 能解释为什么依赖目录、密钥和本机配置通常不应提交。
- [ ] 能使用断点或日志证明一个问题的根因，而非只描述现象。
- [ ] 至少一份 AI 辅助记录包含原始问题、采纳范围、实际验证和独立解释。
- [ ] 已填写 [[../03-执行计划/进度看板|进度看板]]，确定每周固定学习时段。

## 常见误区

- 一开始安装大量框架、插件和主题，却没有完成任何可验证作品。
- 把所有错误交给 AI，不保留错误原文，也无法复述修复原因。
- 把 AI 的“测试通过”“问题已修复”当证据，或为了让建议生效而跳过检查。
- 把 Git 当成云备份；未推送、未验证的仓库仍可能因本机故障丢失。
