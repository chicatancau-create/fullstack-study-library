# 阶段 06：测试、安全与性能

**建议周次：第 25–28 周｜优先级：P0/P1｜目标：用证据降低交付风险，而不是追求表面覆盖率。**

## 阶段目标

- 建立与业务风险匹配的测试策略和威胁建模意识。
- 能定位前后端、数据库和网络性能瓶颈。
- 通过 [[../02-项目实战/项目03-电商交易Demo|项目 03]] 验证库存、订单、幂等和并发。

## 学习清单

### 测试策略

- [ ] 测试金字塔、测试范围、反馈速度和维护成本。
- [ ] 单元测试聚焦业务规则，集成测试聚焦真实边界，E2E 聚焦关键用户路径。
- [ ] 等价类、边界值、状态转换、异常注入和并发场景。
- [ ] 测试数据工厂、隔离、清理和可重复执行。
- [ ] 时间、随机数、第三方服务、邮件、文件和支付的可控替身。
- [ ] 变异测试或主动破坏代码，验证测试不是“永远绿色”。
- [ ] 覆盖率是线索，不是正确性证明；关键风险比百分比更重要。

### 应用安全

- [ ] OWASP Top 10 与 STRIDE 的基础威胁建模。
- [ ] XSS：输出编码、安全富文本清洗、危险 HTML API 的边界。
- [ ] SQL/命令/路径注入：参数化、白名单和最小权限。
- [ ] CSRF、CORS、点击劫持与安全 Header 的作用和限制。
- [ ] SSRF、开放重定向、任意文件上传的路径与内容风险。
- [ ] 认证会话、暴力破解、速率限制、枚举攻击和审计日志。
- [ ] 依赖漏洞、锁文件、秘密扫描、最小权限和密钥轮换。
- [ ] 日志与错误脱敏；不在客户端源码中放服务端秘密。

### 隐私与数据保护

- [ ] 建立数据清单：字段、来源、用途、可见角色、存储位置、保留期限和删除方式。
- [ ] 默认使用合成数据；不为了演示收集真实身份证件、银行卡、精确位置等无关信息。
- [ ] 数据最小化、访问控制、导出/删除、保留到期和备份中的数据生命周期。
- [ ] 第三方 SDK、日志、分析、错误监控和 AI 服务可能接收哪些数据，发送前是否脱敏。
- [ ] Cookie/同意、跨境和行业要求按产品所在地与场景核对；学习计划不能替代专业合规审查。

### 性能与可靠性

- [ ] 先定义指标：延迟、吞吐、错误率、饱和度及核心 Web 指标。
- [ ] 浏览器网络、渲染、长任务、包体、图片、缓存和代码分割。
- [ ] Node.js CPU Profile、事件循环延迟、内存与句柄泄漏。
- [ ] 数据库慢查询、连接池、N+1、锁等待和索引。
- [ ] 负载测试先建立基线，再一次只改变一个变量。
- [ ] 超时、重试预算、指数退避、抖动、熔断和降级。
- [ ] 重试必须结合幂等；无界重试会放大故障。

## 最小实践

在项目 03 中完成：

1. 为订单和库存建立状态机、不变量与风险清单。
2. 测试重复提交、并发下单、库存不足、事务回滚和非法状态跳转。
3. 对富文本、文件上传、认证和越权进行针对性安全测试。
4. 用负载工具记录优化前后的吞吐量、P50/P95/P99 和错误率。
5. 模拟数据库或缓存不可用，验证错误反馈、超时和降级行为。
6. 画一张订单数据流图，标出数据库、日志、备份和模拟第三方；删除一个非必要字段，并验证普通用户无法读取他人数据。

## 阶段验收

- [ ] 核心交易路径具有单元、集成和至少一条端到端测试。
- [ ] 重复请求与并发测试有真实证据，关键不变量未被破坏。
- [ ] 安全测试覆盖认证、越权、注入、XSS 和上传，不声称“绝对安全”。
- [ ] 数据清单与实际字段一致，至少一条权限或删除规则有自动化验证，未覆盖的备份/保留风险有说明。
- [ ] 性能报告包含环境、数据量、工具、参数、基线、结果和限制。
- [ ] 发现的问题按影响与概率排序；高风险问题有修复或明确阻断说明。
- [ ] 所有检查可由命令重复执行，失败不会被静默忽略。

## 常见误区

- 盲目追求 100% 覆盖率，却没有测试订单、权限等高风险规则。
- 把扫描器无高危结果等同于系统安全。
- 只在隐私政策里写“保护数据”，却没有数据清单、最小化和删除验证。
- 在没有基线和剖析数据时随机加缓存、索引或复杂度。
