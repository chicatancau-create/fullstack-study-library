## 四、这轮我自己犯的错（已全部纠正并留痕）

| 错 | 症状 | 纠正 |
| --- | --- | --- |
| 分类按仓库名正则 | `PHP-Interview-QA`、`flink-learning`、`WrenAI` 被塞进「SQL与数据」 | 改按正文关键词判定，最后 7 个由人工定类，理由写入 `category_basis` |
| 机械规则「题面标记≥30 即归题库」 | `mdn/content`、`self-llm`、`ai-engineering-from-scratch-zh` 被误判为题库（文档里的「示例/约束」被算成题面标记） | 人工退回；索引第五节明确：目录只作粗定位，主题以实测计数与 `.source.json` 为准 |
| 移动与补图后未更新记账 | 校验报 `FILECOUNT_DRIFT six-finger 388→876`（补图新增 499 文件） | 全库重算 files/bytes 写回，87 个仓库刷新，漂移归 0 |
| 第二轮删包后没留内容凭据 | 校验报 82 个仓库 `NO_SHA` | 补「本机内容指纹」，并在 `fingerprint_note` 里写明可复现性以「来源URL+分支+采集日期」为准 |
| 抢救脚本重复下载 | `jlevy/the-art-of-command-line` 两个分类各一份 | 按文件名+内容摘要比对确认完全一致后删重复（`consolidate.json`） |
| 抽取函数用了已关闭的 tar 句柄 | 抢救脚本运行时崩 | 抽取函数内部自行打开 tar |
| 正则字符类把反斜杠放在 `]` 前 | `unterminated character set` | 顺序改为 `[\\<>:"|?*]`，并改用运行时 `chr()` 构造 |
| 检索加 `language:markdown` | 结果被打成 0（文档仓库主语言多为 HTML/TS） | 取消该限定，改为「下载后按内容形态判定」，这是本轮方法上的主要修正 |
| 改类后补图仍用旧路径 | `AlgoNote` 报目录不存在，755 张图一张没取 | 复查实际路径后人工归位，并把该缺口如实写进索引第四节而不是抹平 |
