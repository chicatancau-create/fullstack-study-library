# 资料入库与扩充规范

> 单一资源事实源：[[catalog.json|catalog.json]]｜Schema：[[catalog.schema.json|catalog.schema.json]]｜生成视图：[[材料清单]]、[[资料索引]]。本机唯一操作入口：`05-外部资料库/_采集暂存/catalog_tool.py`。本文件不授权下载、镜像、删除、推送或发布；这些动作仍需按风险和用户指令单独确认。

## 一、权威边界

1. **身份、来源、分类、许可、时效、审核和生命周期**：以 `catalog.json` 为长期事实源。
2. **文件数、bytes、Markdown 数**：由原机扫描器计算后写入 catalog；不能手工估算，不能由 MB 反推 bytes。
3. **课程/项目精选关系**：以课程和项目正文中的实际本地链接为来源，生成器自动扫描，不手工双写反查表。
4. **`.source.json`**：迁移输入和本机兼容投影；迁移后不再是唯一完整来源。
5. **`材料清单.md`、`资料索引.md`**：生成视图。统计区禁止手工修改；人工说明可放在生成标记之外。
6. **下载日志、API 响应和临时扫描**：放 `_采集暂存`，不是长期事实源。
7. **历史版本**：由 Git 和既有 `90-历史归档` 承担，不创建项目内 backup/recover 副本。

`_采集暂存/catalog_tool.py` 自 2026-11-07 起**随库版本化**（用户决定）：它是 catalog 的唯一操作入口，干净克隆可用它跑只读 `validate`。其余采集脚本、原始下载物和 JSON 账本仍只留本机、不推远端。`.gitignore` 用 `05-外部资料库/_采集暂存/*` 加单文件取反实现这一例外，不要扩大取反范围。

## 二、字段字典

| 字段组 | 必填语义 | 缺失规则 |
| --- | --- | --- |
| `id` | 规范化 `github:owner/repo`，大小写不敏感 | 不可缺失 |
| `name` | 上游显示名称 | 不可缺失 |
| `source.url / canonical_url` | 原始与规范化官方 URL | 不可缺失 |
| `source.aliases` | 改名、重定向等别名 | 无证据写空数组 |
| `source.branch` | 实际抓取分支 | 未知写 `null`，禁止猜 main/master |
| `source.commit_sha` | 不可变提交 | 未知写 `null` |
| `source.fetched_at` | 抓取时间 | 未知写 `null` |
| `source.upstream_pushed_at` | 上游最后推送日期 | 未知写 `null` |
| `source.upstream_snapshot` | **当前上游快照**：`status`、`checked_at`、`default_branch`、`head_commit_sha`、`note`。由 `snapshot` 子命令用 `git ls-remote --symref` 只读取得 | 只证明检查时刻的默认分支与 HEAD；**不得**回填到 `source.branch` / `source.commit_sha`，也不得当作抓取时证据。不可达/超时如实写状态 |
| `payload.mode` | `reference / mirror / derived` | 不可缺失 |
| `payload.mirror_path` | 相对 `05-外部资料库` 的 POSIX 路径 | 无镜像写 `null` |
| `payload.entry_path` | 仓库入口相对文件（README 或 `.source.json`） | 无镜像写 `null`；迁移时持久化，不按当前盘猜测 |
| `payload.included_in_git` | 是否随 Git 提供 | 布尔值，不写“可能” |
| `payload.availability` | 本机存在/缺失/未随包/仅在线 | 不可缺失 |
| `payload.online_fallback_url` | 干净克隆可用的在线入口 | 必须存在 |
| `integrity.archive_sha256` | 完整压缩包 SHA-256 | 未知写 `null` |
| `integrity.content_fingerprint` | 算法、值、范围、观察时间 | 无证据整体写 `null` |
| `integrity.legacy_fingerprint_12` | 旧 12 位指纹 | 仅兼容展示，不是完整哈希 |
| `classification.primary_category` | 实际镜像主分类 | 必须与路径一致 |
| `classification.category_basis` | 分类依据 | 不可为空 |
| `classification.functions` | 仅 `F1–F6` | 未核实写空数组 |
| `metrics.files / bytes / markdown_count` | 原机实测 | bytes 是显示换算的唯一依据 |
| `metrics.count_scope` | 计数范围 | 必须说明是否含 `.source.json`、`_remote_assets`、派生文件 |
| `license.spdx / detection_status / license_files` | 许可证据 | 未知 `null` + `unknown`，不推断 |
| `freshness.status / note` | 时效状态与完整原文 | 无审核记录用 `unknown` |
| `lifecycle.status` | `candidate / active / rejected / archived` | active 与 tombstone 不混算 |
| `review.status` | `legacy_imported / pending / approved` | 旧数据不得冒充重新审核 |
| `extensions` | 旧字段全量保留 | 不静默丢字段 |

缺失值展示约定：`未知` 表示未获得证据，`—` 表示不适用，真实数值 `0` 保留为 `0`。`?`、`None`、空串只能存在于历史原文，不进入 catalog 语义字段。

## 三、`reference / mirror / derived`

- **reference**：只登记官方在线入口，不下载整仓；适合 Bun/Deno、单篇规范、短期文档和无需离线检索的资源。
- **mirror**：确有离线学习或检索价值，保存上游内容；必须记录来源、分支/commit、archive hash、许可和本地指标。
- **derived**：由本地脚本从上游生成的题面、答案、索引等；必须记录生成脚本、输入版本和与学习记录的隔离方式。

新增候选优先 `reference`。star、热度、关键词和“看起来很多内容”不能单独证明需要镜像。

## 四、统一流程

`candidate → dedupe → precheck → human review → staged fetch → verify → atomic activate → generate → validate`

### 1. 候选

记录规范化 URL、发现时间、搜索词、推荐来源、服务对象（课程/M/E/G/项目/JD 缺口）。初始 `lifecycle.status=candidate`，不能直接 active。

### 2. 去重

依次核对：

1. `id`、canonical URL、aliases。
2. 仓库改名/重定向、fork、上游数字 ID、DOI/ISBN。
3. archive hash 与内容指纹。
4. 标题或内容近重复只产生人工审核提示，不自动删除。
5. 命中 rejected/archived 时展示历史原因，只有新证据才重审。
6. 算法题使用 `leetcode:<slug>` 等稳定题目 ID；翻译、题解和 fork 建关系，不按重复仓库直接删除。

### 3. 自动预检

只读元数据或在隔离暂存区检查：

- 默认分支、不可变 commit、上游推送时间、归档状态。
- 许可证文件与 SPDX。
- 文件数、bytes、正文比例、测试和超长路径。
- 初步分类、功能、时效建议。
- 秘密、恶意路径、超大文件和供应链风险。
- 不执行第三方脚本，不绕过登录、付费、反爬或许可限制。

### 4. 人工审核

必须回答：

- 来源是否真实、官方或可信？
- 是否解决当前明确缺口，而不是继续囤资料？
- 版本是否适用，是否教废弃 API？
- 许可是否允许镜像、派生或再发布？
- 主分类、F1–F6、主题和使用边界是什么？
- 是重复、翻译、fork、替代还是全新资源？
- 只登记在线参考，还是确有离线镜像必要？
- “包含测试文件”和“实际构建运行通过”是否分开记录？

审核通过后 `review.status=approved` 并写 `reviewed_at`、`evidence`。没有审核人时保持 `pending`，不得伪造。

### 5. 抓取与原子落位

- 暂存区下载，记录 commit、archive hash、`fetched_at`。
- 保留 gzip/整包校验、tar 成员扫描、非法路径和 Windows 长路径支持。
- 下载、扫描、许可与人工审核全部通过后才落位。
- 旧 active 在新版本验证成功前保持不变。
- 失败不得把已有 files/bytes 写成 0。
- 每个任务必须以 active、rejected 或明确失败终态结束。

### 6. 激活与生成

- 只有通过人工审核的记录可从 candidate 变为 active。
- 更新 catalog 后运行生成器，再跑校验。
- 生成文件头必须有“由 catalog 生成，请勿手工编辑”标记。
- 表格生成必须转义竖线；解析时排除代码围栏。

### 7. 更新与归档

- commit 未变：只更新 `last_checked_at`，不重写镜像。
- commit 变化：生成候选修订，比较许可、分类、时效、指标和内容变化。
- 许可或分类重大变化必须重新人工审核。
- 更新成功前保留旧快照；成功后由 Git 检查 catalog 和视图差异。
- 归档保留完整元数据、最后可用 commit/hash、原因和 `replacement_id`。
- 删除本地载荷与删除元数据是两个独立决定。
- 在派生题面与学习记录分离前，不得自动覆盖 `_派生视图`。

## 五、状态与终态

| 状态 | 含义 | 允许进入索引 |
| --- | --- | --- |
| candidate | 仅候选，未审核 | 否 |
| active | 已审核且有可用入口 | 是，计入 active 统计 |
| rejected | 明确不采用 | 否，保留原因与证据 |
| archived | 曾采用但不再维护 | 否，保留 tombstone |
| review.pending | 审核未完成 | 否 |
| review.legacy_imported | 旧数据迁移，未重新审核 | 是，但不得声称新审核 |

## 六、本机操作与校验

统一入口，默认只读：

```text
python 05-外部资料库/_采集暂存/catalog_tool.py migrate --write
python 05-外部资料库/_采集暂存/catalog_tool.py scan
python 05-外部资料库/_采集暂存/catalog_tool.py snapshot --write --proxy http://127.0.0.1:7897
python 05-外部资料库/_采集暂存/catalog_tool.py generate --write
python 05-外部资料库/_采集暂存/catalog_tool.py validate --mode strict-mirror
python 05-外部资料库/_采集暂存/catalog_tool.py validate --mode source-only
```

- `migrate` 只用于初始迁移或经审查的强制重建；已有 catalog 时默认拒绝覆盖。
- `scan` 默认只报告 files/bytes/markdown 漂移；仅在确认后 `--write` 写回 metrics，不自动接受上游变化。
- `snapshot` 默认只读，`--write` 才写 `source.upstream_snapshot`；它只记录**检查时刻**的默认分支与 HEAD，`--refresh` 才重查已 checked 的资源，`--limit` 用于限流，`--proxy` 供受限网络使用。**它不会写 `source.branch` 或 `source.commit_sha`。**
- `generate` 只写 `材料清单.md` 与 `资料索引.md` 的生成区。
- `validate` 永不写文件；失败必须输出文件、资源、字段和修复建议。
- 连续执行两次 `generate --write` 必须无额外 diff。
- 原机使用 `strict-mirror`；干净克隆使用 `source-only`。

## 七、校验范围

- JSON 可解析及 Schema 合规。
- ID、canonical URL 唯一；枚举、类型、日期、哈希、模式。
- `replacement_id` 引用完整；active 与 tombstone 不混计。
- 分类、明细、总计一致；bytes 汇总后再换算 MiB/GiB。
- 课程反查关系与正文实际链接一致。
- Markdown UTF-8、单一 H1、代码围栏、表格列数。
- Wiki 与普通本地 Markdown 链接。
- 区分“未随 Git 提供”和“原机真实缺失”。
- strict 模式检查每一条 active 镜像存在且指标无漂移。
- 学习进度、G0–G9、学习证据不参与结构成功判定，也不会被自动改写。

## 八、学习记录保护

- 算法派生题面中的每题记录属于学习证据，不随 catalog 生成覆盖。
- 任何再生成必须比对目标是否包含学习者填写内容；不能先覆盖再解释。
- 学习状态、G 关口、错题与项目证据不在本规范自动更新范围内。
- 外部资料只提供材料；是否达到能力标准仍由课程验收、项目证据和独立实操决定。
