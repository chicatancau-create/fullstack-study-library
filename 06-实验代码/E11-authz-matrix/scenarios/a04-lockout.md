# 场景 A04：登录失败锁定

## 触发条件

同一 `tenant + user` 连续 5 次错误口令登录 `/lab/login`。

## 观察到的现象

| 尝试 | 结果 |
| --- | --- |
| 第 1–4 次错误 | 401，失败计数累加 |
| 第 5 次错误 | 429 `locked_out` |
| 锁定后继续尝试 | 429，不再校验口令 |
| 正确口令 | 登录成功，失败计数清零 |

失败与成功都写 `e11.audit`（`login_failed` / `login_ok`），会话 TTL 由 Cookie `Max-Age` 控制。

## 判读

- `evidence/security.txt` 必须出现 `A04 auth failures: 5 bad attempts -> 429`。
- 没有锁定，口令爆破只受网络延迟限制；有了锁定，还要防拒绝服务（锁定键要按账号而不是全局）。

## 边界

失败计数在单进程内存里，重启即清零；未测分布式计数与解锁等待时间。
