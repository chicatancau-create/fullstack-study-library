# 背压：生产/消费速率变化下的有界性
# 池参数固定 concurrency=4、maxQueue=16，判定上界 pending <= 20

档位              提交   生产耗时(ms)  总耗时(ms)  pending峰值  running峰值  队列峰值  等位次数  pending<=20
生产远快于消费            600          5.8         6.3           20            4        16       580  YES
生产接近消费             300          2.1         2.2            1            1         0         0  YES
生产慢于消费              60        924.3       924.3            1            1         0         0  YES

判定：
- 三档 pending 峰值全部 <= 20：成立
- 三档 running 峰值全部 <= 4：成立
- 三档结束后 running/queued 均归零（无残留）：成立
- 三档任务全部完成、无丢弃：成立
- 生产远快于消费时，总耗时由消费端能力决定，队列只是缓冲，不会把任务堆到内存里
  （pending 卡在 20，生产端通过等位被动变慢：这就是背压）。
- 生产慢于消费时，pending 很小，池处于空转，增大 maxQueue 没有任何收益。
- 说明：本例消费端成本是 setImmediate 回合，绝对耗时只用于横向比较，不作为性能指标。
