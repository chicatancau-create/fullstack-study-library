# E12：负载模型、排队与容量（本地闭环子集）

> 对应 [[../../01-阶段课程/专项-核心原理与深度实验|专项：核心原理与深度实验]] 的 E12。
> 本实验只做**本地闭环、合成 10ms 下游**的三轮采样，不覆盖真实 DB/网络/压测端饱和/开放到达率，也**不代表 G5/G7 或生产容量通过**。
> 环境：Windows 10.0.28000 + Node v24.15.0

## 1. 做了什么、没做什么

做了什么：

- 独立 Node 服务进程（`/work` 固定 10ms 延迟）与独立客户端进程，避免同进程事件循环互相干扰。
- 闭环并发：20 个 worker、每轮 300 请求、预热 40、正式 3 轮。
- 每轮记录完成数、失败数、吞吐、P50/P95/P99、max；三轮同口径输出 JSON。
- 断言：0 失败、P95 ≤ 2000ms、恰好 3 轮；否则非零。

没做什么：

- 没有真实数据库/缓存/消息/外部依赖；没有网络延迟/丢包。
- 没有开放到达率模型、没有 coordinated omission 校正、没有压测端饱和度测量。
- 没有多机/多进程压测、没有 CPU/内存/连接池饱和度指标。
- 没有容量结论；本地数字不能外推为大厂流量。

## 2. 可证伪假设

| # | 假设 | 判定方式 | 实际结果 |
| --- | --- | --- | --- |
| H1 | 20 并发、10ms 下游下，客户端能完成 300 请求且 0 失败 | 三轮闭环 | **成立**：每轮 completed=300、failures=0 |
| H2 | 三轮同口径的 P95 应在同一量级 | 比较三轮 P95 | **成立**：16.65–23.33ms |
| H3 | 吞吐随并发/下游变化，而不是随“轮次”漂移 | 三轮 rps | 约 1202–1292 rps，波动有限 |
| H4 | 任一失败/异常 P95 会让门禁非零 | 阈值与 rc 检查 | 已由脚本断言保证 |

## 3. 工作负载

```text
模型     : 闭环（closed-loop），固定并发 20
每轮请求 : 300
路径     : GET /work?ms=10（服务端 setTimeout 10ms）
预热     : 40 请求（不计入样本）
轮次     : 3
客户端   : Node fetch，与服务端分离进程
```

## 5. 结果（本机一次实际运行）

| 轮次 | completed | failures | rps | P50 | P95 | P99 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| round-1 | 300 | 0 | 1202.31 | 15.4ms | 23.33ms | 25.95ms |
| round-2 | 300 | 0 | 1291.53 | 15.43ms | 16.65ms | 17.23ms |
| round-3 | 300 | 0 | 1267.11 | 15.73ms | 17.9ms | 19.83ms |

原始样本汇总见 `evidence/load.json`，摘要见 `evidence/load.txt`，门禁输出见 `evidence/run.txt`。

读法：

- 10ms 下游 + 20 并发理论上限约 2000 rps；实测 1200–1300 rps，差额来自客户端/服务端开销与事件循环调度。
- P95 波动说明单次样本不能当容量结论；三轮同口径只能说明“本机这一时段”的稳定性。
- 没有测客户端 CPU 饱和度；如果客户端先饱和，服务端容量会被低估。

## 6. 边界

1. **闭环 ≠ 开放到达率**：闭环客户端会随服务变慢而自动降速，可能掩盖排队；开放模型需固定到达率。
2. **没有 coordinated omission 校正**：延迟样本不包含“本应发出但被阻塞”的请求。
3. **合成下游**：10ms `setTimeout` 不代表 DB/网络/锁等待。
4. **同机压测**：客户端与服务端共享 CPU/网络栈，数字不是服务端独立容量。
5. **无资源指标**：没有 CPU/内存/连接池/GC 饱和度，不能定位瓶颈。
6. **不能外推**：本机 300 请求、3 轮，不构成生产容量或 SLO 承诺。
