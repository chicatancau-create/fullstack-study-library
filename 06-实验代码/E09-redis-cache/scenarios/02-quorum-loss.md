# 场景 02：quorum 丢失时，锁服务必须说“不”

## 触发条件

Redlock 用 3 个独立实例、quorum=2。分别让 1 个、2 个实例不可达，再尝试获取同一 key。

## 观察到的现象

| 存活实例 | quorum | 获取结果 |
| --- | --- | --- |
| 1/3（7001 可用，7998/7999 拒绝连接） | 2 | 失败：只拿到 1 个 OK |
| 1/2（7001 可用） | 2 | 失败：只拿到 1 个 OK |
| 2/2（7001、7002） | 2 | 成功：okCount=2 |

失败路径会把已在少数实例上写入的 key 删除，避免留下“半个锁”。

## 判读

- `evidence/redlock.txt` 的 `quorum lost` 与 `quorum kept` 两行必须在同一轮出现。
- 只测“获取成功”不能说明 quorum 生效；必须同时有失败样本。

## 边界

“丢失”用指向未监听端口模拟，不是杀进程/网络分区；没有覆盖多数派恢复后的时钟与 token 冲突。
