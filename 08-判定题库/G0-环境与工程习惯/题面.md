# G0 题面

两题，都围绕「真实 Git 操作 + 最小复现」。

## 题 1 · 冲突合并函数

实现 `resolveConflict(ours, theirs)`：合并两侧变更，保留双方独有行，去掉冲突标记与空行。

要求：
1. 不引入新依赖；Node 24 可直接运行。
2. 边界与失败路径要有明确结果，不静默吞错。
3. 运行公开冒烟：`node 自测脚本/smoke.mjs`。
4. `自测脚本/grade.mjs` 与 `参考答案/index.mjs` 都已公开，做完再对照。

## 题 2 · 遗留仓库接手（固定 fixture）

用 `fixture/build.mjs` 生成一个「交接时留下一堆问题」的仓库，然后在干净 clone 上修到全绿：

```bash
FIX="${TEMP:-/tmp}/g0-fixture"
node fixture/build.mjs "$FIX"
git clone "$FIX/legacy.bare.git" "$FIX/learner"
cd "$FIX/learner" && git checkout main
node <本包绝对路径>/自测脚本/grade-repo.mjs .
```

仓库里埋了五件事：

1. 一个**真实冲突**：`feature/timeout` 与 `main` 都改了 `config/app.env` 相邻行。
2. 一处 **off-by-one 缺陷**：`src/rolling_sum.js` 漏掉最后一位，仓库自带测试能抓到。
3. 一份**合成秘密** `config/local.env`：已 `.gitignore`，但工作区里有；你不能让它进库。
4. 一个**脏工作区**：`README.md` 改到一半 + 未跟踪的 `scratch/`。
5. `docs/RUNBOOK.md` **文档滞后**：写的启动方式已不对，别照抄。

要求：
1. 用 `git merge` 产生真合并提交（HEAD 必须两个父提交），不要 `reset` 丢掉一侧。
2. 冲突按「双方都要」解：`LOG_LEVEL=debug` + `TIMEOUT_MS=60000` + `RETRY=5`。
3. 修 off-by-one，但**不改** `test/rolling_sum.test.js` 的断言。
4. 清掉未跟踪垃圾与半截改动。
5. 修完跑：`node <本包绝对路径>/自测脚本/grade-repo.mjs .`，8 条断言全过。
