# G9 评分指南

- 机器断言：`grade.mjs`（旧单函数）+ `grade-paper-a.mjs`（14 条）+ `grade-paper-b.mjs`（13 条）。任一 fail 即该卷未通过。
- 两卷权重与细分见 `评分规则.json`；自评分用 `node 自测脚本/score.mjs 我的自评分.json` 计算。
- 通过条件：每轮 ≥80 且每维 ≥60%，两轮都通过。这是**你自己**执行的判定；本包不做防作弊。
- 常见错误：
  - A 卷把 `+08:00` 当字符串直接比较（A6 抓）
  - A 卷并发没用同一比较器（`createdAt` 相同就比较 `id`），结果随输入顺序变（A7 抓）
  - A 卷先判 conflict 再判 capacity，导致“超容量”被误报成“冲突”（A3 抓）
  - B 卷幂等只查内存不落键，重放时又扣一次库存（B2 抓）
  - B 卷把 `paid` 事件按 `orderId` 去重（同一订单多次支付是合法的，应按 `eventId`）（B3 抓）
  - B 卷退款只判单笔金额，不判累计（B7 抓）
  - B 卷状态机用 `switch` 兜底 `default: pass`（B5 抓）
- 故障变体见 `故障变体/`（6 条，`npm run evidence` 自动复现）。
