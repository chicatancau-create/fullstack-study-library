## 题 2 · MySQL 隔离与锁

`起始代码/db/mysql_lab.mjs` 有 4 处真实缺陷：

1. `withIsolation` 不切级别（只 `BEGIN/COMMIT`）。
2. `tryReserve` 先查后改，10 并发订 5 件会超卖。
3. `acquireSeat` 不加 `FOR UPDATE`，并发能双双抢到同一座位。
4. `deadlockDemo` 顺序加锁，永远不构成死锁。

```bash
bash scripts/db_setup.sh
node 自测脚本/grade-mysql.mjs 起始代码/db/mysql_lab.mjs     # 目标 7/7
```

额外要求：

- `withIsolation(level, fn)` 里 `SET TRANSACTION ISOLATION LEVEL` 必须是事务第一条语句。
- `tryReserve(sku, qty, { mode })` 支持 `'conditional'`（默认）与 `'optimistic'`；乐观锁必须带 `AND version = ?`。
- `acquireSeat(seatId)` 用 `SELECT ... FOR UPDATE` + 同事务更新。
- `deadlockDemo()` 交叉加锁，返回被检测到的错误码（1213）。

## 题 3 · JVM 线程死锁

`jvm/Deadlock.java` 里有一个「已写好但没验证」的死锁检测器。要求：

1. 交叉加锁真的构成死锁（不是顺序一致）。
2. 用 `ThreadMXBean.findDeadlockedThreads()` 轮询检测，返回死锁环长度。
3. 3000ms 内必须找到 2 条死锁线程。

```bash
cd jvm && javac -d "$TEMP/g7-jvm" Deadlock.java && java -cp "$TEMP/g7-jvm" Deadlock 3000
```
